## 1. 部品選定・実装ルール（当初指示）

- 実装は JLCPCB。部品は Basic Parts のみ。
- PCBA に載せる部品は LCSC で豊富な在庫があるもの。
- 手はんだ部品は秋月電子で在庫があるもの。
- 小さい部品は PCBA に任せる。
- 特殊な部品や調達しにくい部品は極力避ける。
- パーツの種類や点数は減らす。
- 目指すのは「設計できる」ではなく「実際に作れる安価な」基板。

## 2. 製品要求（当初指示）

- ゲームセンター用のアーケード基板。JAMMA 端子。
- ファミリーコンピュータ（日本販売品）がベース。主要部品は CPU と PPU のみをファミコンから取り外して移植する。
- もしくは Raspberry Pi 等を実装し、CPU・PPU をエミュレートさせる。両方を選択できること。

  また、第2回指示の「ソフトウェアで切り替え」は方式と入力形式についてのもので、この選び方には及ばない。）
- ファームウェアの更新は USB 等で簡単に行えること。

## 3. 動作方式と入力形式（現行）

### 3.1 ユーザー指示の原文（第3回・2026-11-10）

> タイマー方式の場合はコイン投入後にコントロールが一定時間解放されるルールとして１Pボタン側がスタート、セレクトが２Pボタンになる様にしておいてください、
> そうするとスタートをCボタン替わりに使う可能性があるので、コイン投入方式とスタートの形式を設定できる様にします。
> デフォルトは「上下左右AB　スタート　セレクト（コイン）」を1P2Pで設定します（２P側のスタートセレクトは基本使わない形になりますが、ゲームの方では使える様にします。）
> モード特殊を設定しこの場合は「上下左右、AB　C（セレクトボタン）　D（スタートボタン）とし、　ゲームスタートスタート（左右同時）　COIN（上下同時）」を１P2Pに設定します。
>
> 市販ソフトはタイマーで動かす事とします。上記形式は新規開発のファミコンゲームで使える様にします。

### 3.2 全体の構成

- 動作方式は2つある。
  - **タイマー方式**: 市販ソフトを動かすための方式。
  - **通常方式**: 新規開発するファミコンゲームのための方式。
- 通常方式には入力形式が2つあり、設定で選ぶ（「コイン投入方式とスタートの形式を設定できる」）。
  - **デフォルト形式**
  - **特殊形式**（モード特殊）
- 方式と形式の切り替えはソフトウェアで行う（4 章）。

ファミコンのパッドは A, B, SELECT, START, 上, 下, 左, 右 の順に1ビットずつ読み出される（ビット0〜7）。
以下、「I コン」は 1P 側のパッド（$4016 で読む）、「II コン」は 2P 側のパッド（$4017 で読む）を指す。

### 3.3 タイマー方式（市販ソフト用）

- コインを入れると、一定時間だけ操作が解放される。時間が切れると操作を受け付けなくなる。
- コインはゲームへの入力としては渡さず、時間の加算だけに使う。

| JAMMA の入力 | ピン | ゲームから見える入力 |
|---|---|---|
| 1P レバー上下左右 | 18〜21 | I コンの上下左右 |
| 1P ボタン1（A）・ボタン2（B） | 22・23 | I コンの A・B |
| 1P スタートボタン | 17 | I コンの START |
| 2P スタートボタン | U | I コンの SELECT |
| 2P レバー上下左右 | V〜Y | II コンの上下左右 |
| 2P ボタン1（A）・ボタン2（B） | Z・a | II コンの A・B |
| コイン1・コイン2 | 16・T | ゲームには渡さない。プレイ時間を加算する |
| ボタン3（C）・ボタン4（D） | 24・25・b・c | 使わない |

### 3.4 通常方式・デフォルト形式（新規開発ゲーム用）

1P・2P それぞれについて、次のとおり。

| JAMMA の入力 | 1P 側ピン | 2P 側ピン | ゲームから見える入力 |
|---|---|---|---|
| レバー上下左右 | 18〜21 | V〜Y | そのパッドの上下左右 |
| ボタン1（A）・ボタン2（B） | 22・23 | Z・a | そのパッドの A・B |
| スタートボタン | 17 | U | そのパッドの START |
| コイン | 16（コイン1） | T（コイン2） | そのパッドの SELECT |
| ボタン3（C）・ボタン4（D） | 24・25 | b・c | 使わない（指示に記載なし） |

- 2P 側の START・SELECT は基本的に使わないが、ゲームから読めるようにしておく。
- ゲームは START を C ボタンの代わりに使う可能性がある。

### 3.5 通常方式・特殊形式（新規開発ゲーム用）

1P・2P それぞれについて、次のとおり。

| JAMMA の入力 | 1P 側ピン | 2P 側ピン | ゲームから見える入力 |
|---|---|---|---|
| レバー上下左右 | 18〜21 | V〜Y | そのパッドの上下左右 |
| ボタン1（A）・ボタン2（B） | 22・23 | Z・a | そのパッドの A・B |
| ボタン3（C） | 24 | b | そのパッドの SELECT |
| ボタン4（D） | 25 | c | そのパッドの START |
| スタートボタン | 17 | U | そのパッドの左と右を同時に押下 |
| コイン | 16（コイン1） | T（コイン2） | そのパッドの上と下を同時に押下 |

- ゲームは A・B・C・D の4ボタンを、レバーと独立して使える。
- ゲームは「左右同時」をゲームスタート、「上下同時」をコイン投入として解釈する。

### 3.6 この整理で補った前提（ユーザー未確認）

- タイマー方式の「セレクトが2Pボタン」は、**2P スタートボタンを I コンの SELECT として使う**と読んだ。
- デフォルト形式では、筐体の C・D ボタンは何にもつながないと読んだ。
- タイマー方式の時間切れは、操作を受け付けなくするだけで、ゲームのリセットはしないと読んだ。
- タイマー方式では、コイン1・コイン2のどちらでも時間が加算されると読んだ。
- ボタン名は日本の業務用筐体の慣例どおり、JAMMA のボタン1=A、ボタン2=B、ボタン3=C、ボタン4=D と読んだ。
  ボタン4（ピン25／c）は JAMMA の正式規格外で、慣例的に使われている拡張割り当てである。
- 第2回指示の「C=上下同時、D=左右同時」は、この第3回指示で置き換えられたと読んだ（9 章に履歴）。

### 3.7 この仕様から生じる設計上の帰結（推論）

- **特殊形式は、レバーが物理的に作れない入力をコインとスタートに使う。**
  正常なレバーは上下・左右を同時に閉じられないので、プレイヤーの操作と誤認されない。
- **特殊形式では、コインのパルス中は上下が、スタートを押している間は左右が読めなくなる。**
  ゲーム側は、同時押しを検出したフレームではその軸の入力を無視する必要がある。
- **コインの信号は整形してから出す必要がある。**
  コインスイッチの閉じる時間は機構によってまちまちで、1フレームより短いとゲームが取りこぼす。
  任天堂 VS. システムの実機は 2.5〜4 フレーム幅だった（coin_op_precedents_and_legal.md 参照）。
  複数枚の連続投入は待ち行列にして、1枚ずつ間隔を空けて出す。
- **2P 側の START・SELECT は、初代ファミコンには存在しないビットである。**
  初代機の II コントローラは、この2ビットが常に「押されていない」と読める。
  本基板では AV ファミコンや NES と同じく 2P 側にも実ビットを出す。
- **タイマー方式で時間切れになったあとの扱いは未定である。**
  操作を止めるだけだと、次の客は前の客が残した場面から始めることになる。
  ファミコンのリセットボタンに当たる入力も JAMMA にはない。
- **タイマー方式には残り時間の表示手段が必要である。**
  任天堂の PlayChoice-10 とファミコンボックスは、どちらも残り時間や時間切れの予告を客に知らせていた。

## 4. 切り替え手段はソフトウェア（第2回指示・2026-11-10・現行）

ユーザー指示の原文:

> ソフトウェアの方でタイマー方式と通常の方式と切り替え可能としてください。

### 4.1 この指示の読み方

- 当初は「DIP スイッチ（ハードウェア側）で選ぶ」としていた切り替えを、**ソフトウェア側で切り替えられるようにする**。
- 第3回指示で、切り替える対象に「コイン投入方式とスタートの形式」（3.4 と 3.5 の入力形式）が加わった。
- 「ソフトウェア」が指す対象は2通りに読める。どちらも満たす設計にしておく（4.2）。
  - 読み方A: 基板のファームウェアの設定として切り替える（物理スイッチに頼らない）。
  - 読み方B: 新規開発したゲームカートリッジのプログラムから、基板の方式・形式を切り替える。
- 方式・形式用の物理 DIP スイッチを残すかどうかは未確認。部品点数を減らす方針からは、なくせるものはなくすのが筋である。

### 4.2 両方の読み方を満たす実現方法（推論）

- **方式と形式はファームウェアの設定値として不揮発メモリに保存する。**
  対象は、タイマー方式／通常方式、デフォルト形式／特殊形式、1コインあたりの時間など。
- **店舗の担当者が工具なしで変更できる経路を2つ用意する。**
  - 筐体のテストスイッチ（JAMMA ピン15）で設定画面を出す。映像をマイコンが作り直す構成なら、設定画面はマイコンが直接描けるので追加部品は要らない。
  - USB 接続で設定を書き換える。ファームウェア更新と同じ USB 端子を使う。
- **新規開発カートリッジからの切り替えは、既存の信号線だけで実現できる。**
  - ゲーム→基板: $4016 への書き込みで動く OUT1・OUT2（標準パッドでは未使用）に決まった手順のビット列を出す。
  - 基板→ゲーム: $4016 の D1 と $4017 の D1〜D4（拡張端子用の読み出しビット）で、設定値やクレジット数を返す。
  - 任天堂 VS. システムが DIP スイッチやコインを $4016/$4017 のビットで読ませていたのと同じ考え方である。
  - この通信手順は本プロジェクトで新たに決める必要がある（未設計）。
- **市販ソフトは基板に指示を出せない**ので、市販ソフトを動かすときは担当者がタイマー方式に設定する。

## 5. Raspberry Pi の枚数と将来の更新（第4回指示・2026-11-10・現行）

ユーザー指示の原文:

> ラズパイは何枚使ってもかまいません。将来的にCPU、PPU、各種メモリのアップデートも視野に入れてください。

### 5.1 この指示の読み方

- Raspberry Pi（Pico を含む）は、1枚に収める必要はない。必要な枚数を使ってよい。
- CPU、PPU、各種メモリを、将来より新しいもの・より高性能なものに更新できる余地を、いまの設計に残しておく。
- 「アップデート」が、部品の差し替えを指すのか、性能や仕様の拡張を指すのかは未確認。両方に備える前提で整理する（5.2）。

### 5.2 設計への反映方針（推論）

- **マイコンは役割ごとに分けて複数枚にする。** 1枚では入出力ピンが足りないという制約がなくなる。
  例: 映像変換用、入出力とコイン・タイマー制御用、CPU/PPU のエミュレーション用。
- **CPU と PPU はソケット実装を守り、差し替えの経路を残す。**
  実チップの代わりに、同じソケットに挿せる代替モジュールや、エミュレーション用マイコンへ切り替えられるようにする。
- **エミュレーション側は、ファームウェア更新だけで仕様を拡張できる。**
  新規開発ゲーム向けに、本来のファミコンを超える性能を後から足す余地になる。
- **メモリは最初から余裕のある容量を載せ、上位アドレスを後から使えるようにしておく。**
  初期状態はファミコンと同じ 2KB の見え方に固定し、配線だけ先に用意する。
- **拡張用のコネクタを用意する。** CPU バス、PPU バス、音声、映像、予備のマイコン端子を引き出しておけば、基板を作り直さずに後から機能を足せる。
- **映像と音声の出力回路には余裕を持たせる。** 色数や音質を後から上げられるよう、DA 変換のビット数を本来の必要分より多めにとる。
- **複数枚のマイコンを1つの USB 端子から更新できるようにする。** 枚数が増えても、更新の手間を増やさないため。

## 6. USB Type-C によるファームウェア更新（第5回指示・2026-11-10・現行）

ユーザー指示の原文:

> USB-cを内包しファームのアップデートができる事としてください

### 6.1 この指示の読み方

- 基板上に USB Type-C の端子を持たせる。
- その端子からファームウェアを更新できるようにする。
- 当初指示の「ファームウェアの更新は USB 等で簡単に行えること」を、端子の種類まで具体化したものと読んだ。

### 6.2 実現するうえでの論点（推論。出典は各調査ノート）

- **Raspberry Pi Pico 2 の USB 端子は Micro-B で、Type-C ではない。** USB の信号線は 40 本の端子列には出ておらず、基板裏のテストパッドにしかない。
  そのためピンソケットで挿す構成のままでは、基板側の Type-C 端子に USB 信号を渡せない。
- **Type-C 端子の部品はどちらの調達先にもある。**
  JLCPCB では 16 ピンの Type-C 端子（C393939）が在庫豊富だが、分類は Extended である（parts_class_reverification.md）。
  秋月には基板用の 16 ピン端子（販売コード 114356、在庫僅少）と DIP 化基板（113080）がある（parts_round2_sourcing_and_cost.md）。
- **実現方法の候補は3つある。**
  - マイコンのチップ（RP2350）を基板に直接実装し、Type-C 端子を直結する。配線は最も素直だが、チップと端子が Extended 部品になる。
  - Pico 2 を基板に直接はんだ付けし、裏面のテストパッドを基板側の穴越しにはんだ付けして Type-C 端子へつなぐ。
  - 基板に Type-C 端子を置き、Pico 2 の Micro-B 端子へ短いケーブルで中継する。
- **マイコンを複数枚にする場合、Type-C 端子は1つにまとめたい。**
  端子につながる1枚が他の枚のファームウェアも書き換える方式か、USB ハブ IC を載せる方式になる（5.2 の最後の項目）。
- **RP2350 は USB からの書き込み機能を書き換え不能な領域に持つ。** 更新に失敗しても、書き込みモードに入り直してやり直せる（raspberry_pi_emulation_path.md）。

## 9. 置き換えられた過去の指示（履歴）

### 9.1 当初の入力仕様（第1回指示）

- セレクトボタンをコインシューターとする（DIP スイッチでスタートボタンをコインシューターにもできる）。
- 1P コントローラーの上下左右同時押しを 1P スタート、2P コントローラーの上下左右同時押しを 2P スタートとする
  （特殊仕様として DIP スイッチで設定できる）。

### 9.2 第2回指示の入力マッピング（第3回指示で置き換え）

> JAMMAの配線として１P.２P共に上下左右とABボタンはそのまま、コイン投入はセレクト、スタートボタンはスタートとしてください、Cボタンは上下同時押し、Dボタンは左右同時押しをもって対応する設計にしてください。

- このうち「上下左右・A・B はそのまま、コインは SELECT、スタートは START」は、第3回指示のデフォルト形式に引き継がれた。
- 「C=上下同時、D=左右同時」は、第3回指示の特殊形式（C=SELECT、D=START、スタート=左右同時、コイン=上下同時）に置き換えられた。
