# コイン・スタート・時間制の仕組みと法的論点 - リファレンスシート

- **タイマー方式（市販ソフト用）は、技術的には任天堂の PlayChoice-10 とファミコンボックスの先例どおりに作れる。** コインはゲームに渡さず時間だけを加算し、時間切れでは即リセットせずに猶予を置く点が両先例に共通する。猶予の後に CPU をリセットして待機画面に戻す流れは、ファミコンボックスでは実機観察（単一出典）、PC-10 では推論である。
- **ゲームに見せるコイン入力は、ラッチ 4 回以上かつ 67 ms 以上押し、同じだけ離してから次を出す。** 連続投入は待ち行列（上限 15）に入れて 1 枚ずつ出す。1 フレーム幅では取りこぼすゲームが実在する。
- **市販ソフトには上下同時・左右同時を絶対に送らない。** プレイ中に送ると続行不能になるソフトがある（Battletoads ほか）。上下同時・左右同時を使う特殊形式は、新規開発ゲーム専用である。タイマー方式では II コンの SELECT・START ビットを 0 に固定する。
- **最大の法的論点は著作権の上映権である。** 市販ソフトを料金を取って客に遊ばせると、権利者の許諾がない限り上映権侵害になるリスクが高い（条文と 2018 年のゲームバー経営者 4 名の逮捕からの推論。正規品の家庭用ソフトについての判決は見つかっていない）。ユーザー要求の「市販ソフトはタイマーで動かす」は、権利者の許諾を得たソフトに限らない限り営業には使えない（推論）。
- **設置先は風営法 5 号営業の許可のある店舗等に限られ、基板に景品払出しや得点の持ち帰り機能を付けてはならない。** 中古本体からチップを取り出して基板を販売する事業には、古物商許可が必要になる可能性が高い（警察庁の解釈運用基準と県警の例示からの推論）。
- 本シートの法的事項は技術者向けの背景情報であり、法的助言ではない。

## 1. 確定事実

### 1.0 本シートでの用語と確度の印

- **I コン / II コン**: ゲームから見た 1P 側パッド（$4016 で読む）と 2P 側パッド（$4017 で読む）。
- **ラッチ**: ゲームが $4016 の bit0（2A03 の OUT0 端子、ストローブ）に 1 を書いてから 0 に戻し、パッドのボタン状態を確定させる操作。1 回のラッチの後、ゲームは 8 回読み出して 8 ボタン分の状態を得る。
- **フレーム**: 画面 1 枚の周期。約 1/60 秒。多くのゲームは 1 フレームに 1 回パッドを読む。
- **パルス**: コインなどを「一定時間だけ押された状態」にしてゲームに見せること。その長さをパルス幅という。
- **猶予**: 時間切れのあと、追加コインを待つ時間。
- **アトラクト**: 客がいない間にゲームが流すデモ画面。
- **確度の印**: **確認済** = 2 つ以上の独立した出典、または回路図・データシート・条文原文・ソースコードなどの一次資料で確認したもの。**単一出典** = 出典が 1 つだけのもの。**未確認** = 出典で確かめられていないもの。
- **推論** と書いた箇所は、出典のある事実ではなく、調査者または本シート作成者の判断である。

### 1.1 ファミコンのパッド読み出しの基礎（設計の前提）

| 項目 | 事実 | 確度 |
|---|---|---|
| ボタンの順序 | ビット 0〜7 の順に A, B, SELECT, START, 上, 下, 左, 右。HVC-CPU-05 の回路図では 4021 の P8=A, P7=B, P6=SELECT, P5=START, P4=UP, P3=DOWN, P2=LEFT, P1=RIGHT | 確認済 |
| ストローブ | $4016 書き込み bit0（OUT0、2A03 の 39 番ピン）が両パッドの 4021 の P/S に入る。1 の間は連続ロード、1→0 で確定する | 確認済 |
| 読み出し | $4016 読み出しで /OE1（36 番ピン）、$4017 読み出しで /OE2（35 番ピン）がアクティブになる。その間だけ 40H368 が M2 を反転したクロックをパッドに出し、読み出し終了の立ち上がりでシフトする | 確認済 |
| 8 回読んだ後 | 公式コントローラは 1 を返し続ける（DS = GND） | 確認済 |
| ファミコンの読み出しビット | $4016 D0 = I コン、D1 = 拡張端子、D2 = マイク（II コン）。$4017 D0 = II コン、D1〜D4 = 拡張端子（D3/D4 はザッパーが使う）。bit5〜7 はドライブされず、直前のバスの値（通常は $40 の上位 010）が残る | 確認済 |
| オープンバス依存 | 上位ビットに直前の値が残ることに依存するソフトがある（"Paperboy"、Mindscape 系） | 確認済 |
| II コンの SELECT / START | HVC-001 の II コンには SELECT と START が無く、4021 の P6/P5 は VCC に直結され、常に「押されていない」と読める。NESdev は「ファミコン用ソフトは II コンの Start / Select に頼ってはならない」とする | 確認済 |
| AV ファミコン | II コンにも SELECT / START があり、マイクは無い | 単一出典 |
| マイク | $4016 D2 に読むたびの瞬時値が出る。使うソフトは『バンゲリング ベイ』『スターラスター』『たけしの挑戦状』『ゼルダの伝説』『ドラえもん（ハドソン版）』『スターソルジャー』、ファミリーベーシック V3 のサンプル『ハート』など。本体の製造時期によってオン/オフの判別が逆にされたという記述がある | 単一出典 |
| 拡張端子コントローラ | D1 で同じ 8 ビットを返し、多くのゲームが D0 と D1 を OR して読む（対応しないゲームもある） | 確認済 |
| OUT1・OUT2 | $4016 書き込みの bit1・bit2 がそれぞれ OUT1（38 番ピン）・OUT2（37 番ピン）にラッチされる。標準パッドでは使わない。APU サイクル（2 CPU サイクル）ごとに更新される | 確認済 |
| DPCM 読み出しグリッチ | DMC の DMA が $4016/$4017 の読み出しと同じサイクルに起きると、余分なクロックが入ってビットが欠け、典型的には「右」の誤検出になる。NTSC の 2A03 は影響を受ける（PAL の 2A07 で修正） | 確認済 |
| リセット | HVC-CPU-05 では CPU /RST のみがリセットされ、PPU /RST は +5V に固定されている | 確認済 |

### 1.2 任天堂 VS. システム（VS. UniSystem / DualSystem）

VS. システムは、コインとスタートをどう渡していたかの先例である。コインはパッドのシフトデータには入れず、$4016 の上位ビットとして直接読ませていた。クレジットの管理はゲームソフト側が行い、ハードにクレジットカウンタは無い。

| 項目 | 事実 | 確度 |
|---|---|---|
| CPU / PPU | CPU は常に無印リビジョンの RP2A03（2A03G とは非互換）。PPU は RGB 出力の 2C03 / 2C04 / 2C05 | 単一出典（NESdev。原文 "The CPUs are always the letterless revision" を再確認） |
| $4016 読み出し | bit0 = 右スティックの直列データ（A, B, 1, 3, Up, Down, Left, Right の順）、bit1 = 常に 0（74LS240 の浮き入力）、bit2 = サービスボタン（クレジット投入）、bit3-4 = DIP「2」「1」、bit5-6 = コイン投入、bit7 = 0:メイン CPU / 1:サブ CPU | 確認済 |
| $4017 読み出し | bit0 = 左スティック（A, B, 2, 4, Up, Down, Left, Right の順）、bit1 = 常に 0、bit2-7 = DIP「8」〜「3」 | 確認済 |
| スタートボタンの位置 | スタート 1/2 はシフトの 3 番目（家庭用の SELECT の位置）。DualSystem のスタート 3/4 は 4 番目（START の位置）。UniSystem では START の位置は未使用（MAME の定義で 0x08 = IPT_UNUSED） | 確認済 |
| マニュアルでの呼び名 | VS. System Upright（MDS-UP-US）の配線表で、スタートボタン線は "S SELECT 1"〜"S SELECT 4" と "M SELECT 1"〜"M SELECT 4" | 単一出典 |
| 左右の対応 | 左スティック → $4017、右スティック → $4016（家庭用と逆）。多くのゲームは左を P1 とみなすが、SMB・TKO Boxing・Mighty Bomb Jack は右を P1 とみなす | 確認済 |
| コインのビット | コイン 1/2 は別ビット。"games MUST check both bits"（両方のビットを確認しなければならない） | 確認済 |
| コイン信号の長さ | NESdev は "approximately 40 to 70ms" true になると書く。MAME は「実機テストではコイン落下時間は 2.5〜4 フレーム」と書き、`PORT_IMPULSE(3)`（3 フレーム）で入力する。両者は同じ範囲を指している | 確認済 |
| 1 フレームでは短い | MAME のコメント: "1 frame is too short for some games (T.K.O. Boxing)" | 単一出典 |
| コインカウンタ | $4020 bit0 に 1、続けて 0 を書くと 1 カウント進む。$4020-$5FFF にミラー。10 Hz のカウンタは 50 ms High / 50 ms Low で確実に駆動できる。電源投入とリセットでクリアされる | 単一出典 |
| ウォッチドッグ | サブ CPU（ソケット 8J）が 1.2 秒以内ごとに $4017 を読まないと、両 CPU・両 PPU・$4020 をリセットする | 確認済 |
| 無改造ソフトを動かした場合 | START の位置に入力が無いのでゲーム開始もポーズもできない。左側の操作パネルは P2 扱いになる。$4016 の全ビットを比較するソフトは誤作動する（`and #3` でマスクするソフトは問題ない）。DIP の値がザッパー入力として見える。2C04 では色化け、2C05 では $2000 と $2001 が入れ替わる。ネームテーブルは常に 4 画面 | 単一出典（各事実は確認済、「影響」の判断は推論を含む） |

### 1.3 任天堂 PlayChoice-10（PC-10）

PC-10 は「コイン = プレイ時間」の先例である。Z80 の BIOS が残り時間を管理し、ファミコン側（N2A03）の CPU・PPU・入力・映像・音声を個別の信号で制御した。

| 項目 | 事実 | 確度 |
|---|---|---|
| 構成 | Z80 @ 4 MHz + N2A03 @ 1.789772 MHz。コインはクレジットではなく時間を加算する | 単一出典 |
| BIOS 入力ポート 0 | bit0 CHSelect、bit1 Enter、bit2 Reset、bit3 INTDETECT、bit5 Coin2、bit6 Service、bit7 Coin1。ポート 1/2 は DIP1/2 | 単一出典（MAME） |
| 出力ラッチ LS259 #1（7D） | Q0=SDCS、Q1=/CNTRLMASK、Q2=/DISPMASK、Q3=/SOUNDMASK、Q4=/GAMERES、Q5=/GAMESTOP | 単一出典（MAME） |
| 出力ラッチ LS259 #2（7E） | Q0=NMI Enable、Q1=DOG DI、Q2=/PPURES、Q3-Q6=CSEL0-3（カートリッジ選択 0〜9）、Q7=8UP | 単一出典（MAME） |
| /GAMERES と /GAMESTOP | MAME では /GAMERES は 2A03 の RESET 入力に、/GAMESTOP は 2A03 の HALT 入力につながる（どちらも反転） | 単一出典（MAME） |
| /CNTRLMASK のマスク対象 | ストローブの立ち下がりで P1 の値をラッチし、`m_input_latch[0] &= ~0x0c;`（コメント "mask out select and start"）で SELECT（0x04）と START（0x08）の 2 ビットだけを消す。ガンゲームではザッパーのトリガ（$4017 bit4）も消す。光センサ（bit3）、十字キー、A/B、P2 は消さない | 単一出典（MAME のソースコード） |
| P2 の SELECT / START | 筐体には P1 用の Game Select と Start しかない。MAME では P2 の 0x04/0x08 が IPT_UNUSED で、"wired to 1p select button" / "wired to 1p start button" と注記 | 単一出典 |
| /DISPMASK | シングルモニタ版では切り替えるたびにゲーム画面と BIOS 画面を入れ替える。デュアルモニタ版では下画面（ゲーム）を黒で塗りつぶす | 単一出典（MAME） |
| /SOUNDMASK・/PPURES | /SOUNDMASK はシステム全体をミュート、/PPURES は PPU をリセット | 単一出典（MAME） |
| 残り時間の表示 | シングルモニタ版 BIOS は I/O $10-$13 に 4 桁の BCD で残り時間を書き、7 セグ LED に表示する。デュアルモニタ版は上画面にメニュー・説明・残り時間を出す。VS. UniSystem 用キットにも "8. LED PC Board indicate player time." という確認項目がある | 確認済 |
| 時間切れの挙動 | 時間切れになると下画面（ゲーム）が黒くなり、上画面が "gives you 20 seconds to insert a coin"。"Put one in and the game springs back into action."（コインを入れるとその場から再開） | 単一出典（Atari HQ。MAME の配線と矛盾しない） |
| 時間切れの判断 | ドライバ側に時間切れ処理は無く、Z80 BIOS ROM が決める | 単一出典 |
| 1 コインの時間（既定） | 1 クォーターで 300 秒。いつでもクォーターを足せば 300 秒延びる | 単一出典（Atari HQ） |
| マニュアル PCH1-UP の記載 | 工場出荷時設定は "STANDARD TIME (no bonus)"。例として "Regular Time 1 COIN = 300 (3 min.)" と "PRIME TIME 4 COINS = 1200 (12 min.)" がある。OCR の品質が低く、300 が秒か単位か、「3 min.」との整合は未確認 | 未確認 |
| DIP（MAME） | "Play Time/Coin": Standard Time で 2:00〜4:50（10 秒刻み）、Prime Time で 2:00〜4:00。"Bonus": Standard Time / Prime Time for 2 Coins / Prime Time for 4 Coins。"Prime Time Bonus": 8〜100% | 単一出典 |
| DIP（マニュアル準拠、MAME でコメントアウト） | "Timer speed" 60〜1 units per second、1 unit every 4 seconds、Free Play。DSWB bit7 ON で Free Play（9999 units） | 単一出典 |
| 最短時間・追加コイン | 最短 2 分。プレイ前に追加のコインを入れると Prime Time のボーナスが付く。ボタンでゲーム選択メニューを呼び出して切り替えられ、ポーズとリセットもできる | 単一出典（Wikipedia が Cashbox 1986-08-30 p.41 などを引用） |
| 説明画面 | プレイ中に Enter を押すと説明画面が出る（"This apparently overrides the video from the game or halts the 2A03E CPU's execution"）。Enter を 2 秒押し続けるとゲームに戻る | 単一出典 |
| 自己診断への入り方 | (a) アトラクト中かゲーム中に Service と Enter を同時に押す、(b) Service を押しながら電源を入れる（ブックキーピング RAM をリセットできる）、(c) SW1 のトグル H を ON にして電源を入れる | 単一出典 |
| フリープレイの欠陥 | フリープレイ時はアトラクトモードが走らない | 単一出典 |
| 後継機 NSS（1991） | Z80 のポート 01h の bit1 が "Maybe SNES CPU pause? (cleared on deposit coin to continue)"、bit0 が CPU/PPU リセット、bit7 が "SNES Joypad Enable (0=Disable/Demo)"、bit5 が "SNES Sound Mute"。MAME は bit1 を CPU の HALT につなぐ | 単一出典 |

推論（調査者）: PC-10 の時間切れは「/GAMESTOP で CPU 停止 + /DISPMASK でゲーム画面を黒 +（おそらく）/SOUNDMASK → 20 秒待つ → コインが無ければ /GAMERES でリセットしてメニューへ」と考えられる。BIOS がラッチに書く順序は未確認。2A03 にはピンとしての RDY が無いので、/GAMESTOP が実機で何を操作していたかも未確認である。

### 1.7 JAMMA 側のコイン信号・カウンタ・ロックアウトの電気的事実

JAMMA のピン: コイン 1 = 16、コイン 2 = T、コインカウンタ 1 = 8、コインカウンタ 2 = J、ロックアウト 1 = 9、ロックアウト 2 = K、サービス = R、テスト = 15、ティルト = S。入力はすべて GND に落とすと有効（アクティブ Low）。サービス（R）はクレジットを +1 するがカウンタは進めないのが慣行である。

### 1.10 現行の要求仕様に対する動作仕様の案（推論）

この節は、1.1〜1.9 の事実をもとに、現行の要求仕様（タイマー方式、通常方式のデフォルト形式と特殊形式、ソフトウェアでの切り替え）に合わせて組み直した設計案である。**すべて推論**であり、根拠の確度は各事実の節を参照する。調査ノートの案のうち、古い要求（スタート = 上下左右同時押し、DIP スイッチ 8 極での切り替え、Pico 1 枚）を前提にした部分は採らず、現行の要求で置き換えた。

前提: 基板のマイコン（以下「入出力マイコン」）が JAMMA の入力をデバウンスし、ファミコンから見たパッドの 4021 シフトレジスタの代わりを務める。入出力マイコンは OUT0 の立ち下がりを数えてラッチ回数とする。エミュレーション用マイコンを使う構成では、同じ処理をエミュレータ内で行う。

#### 1.10.3 タイマー方式の状態と時間切れの手順

| 状態 | 入ったときの条件 | ファミコン側の状態 | プレイヤーへの表示・音 | 次の状態 |
|---|---|---|---|---|
| 待機 | 電源投入、または終了後 | 2A03 の /RES と 2C02 の /RST を Low に保持する | 入出力マイコン（または映像マイコン）が「INSERT COIN」と 1 コインあたりの時間を描く | コイン投入でプレイ中へ |
| プレイ中 | 1 枚目のコイン（ファミコンボックスと同じく 1 枚目でタイマー開始） | リセット解除。入力は 1.10.1 のとおり素通し | 残り時間を画面の隅に重ねて表示（設定で OFF 可） | 残り時間が警告時間以下で警告へ |
| 警告 | 残り時間が設定した警告時間（30 秒または 60 秒）以下 | プレイ中と同じ | 約 1 Hz で 874 Hz のビープ（設定で OFF 可）。残り時間の表示を点滅 | 0 秒で猶予へ。コインでプレイ中へ戻る |
| 猶予 | 残り時間 0 | 両パッドの全ビットを 0 にする。CPU のクロックは止めない（ゲームは裏で動き続ける） | 映像をおよそ 45% まで暗くする。ゲームの音を消す。「CONTINUE? 残り xx 秒」を重ねて表示 | コインが入ればマスクを解いてプレイ中へ。猶予時間（20 秒または 60 秒）が過ぎたら終了へ |
| 終了 | 猶予切れ | 2A03 /RES と 2C02 /RST を同時に Low にして保持する。電源は切らない（電池付き SRAM の破損を避ける） | 「TIME UP / SEE YOU NEXT」を約 5 秒表示 | 待機へ |

- **コインを入れたとき**: 残り時間に 1 コインの時間を加える。上限は 99 分 59 秒。コインはゲームに見せない。
- **やり直し**: 1P スタートを 3 秒押し続けるとリセットする（ファミコンボックスのリセットボタンに相当）。時間は減らさない。押し始めの時点でゲームがポーズするが、直後にリセットされるので害は小さい。
- **フリープレイ**: タイマーを止め、リセットを常に解除しておく。
- **CPU を止めない理由**: NMOS の 6502 はレジスタがダイナミックなので、クロックを長く止めると内容を保てない可能性がある（一般知識。一次資料は未確認）。そのため猶予中はゲームが動き続け、キャラクタがやられることがある。エミュレーション構成なら、エミュレータを一時停止して PC-10 と同じ「その場で止めて待つ」動作にできる。

#### 1.10.6 新規開発ゲームと基板の通信、任意のマイク入力

- **ゲーム → 基板**: $4016 書き込みの OUT1・OUT2 に、決まった手順のビット列を書く（標準パッドでは使わない線）。
- **基板 → ゲーム**: $4016 D1 と $4017 D1〜D4 で、設定値やクレジット数を返す。ただし多くのゲームが D1 を D0 と OR して読むため、**通信手順がゲーム側から開始されるまでは、これらのビットを「押されていない」状態に固定する**。$4017 D3/D4 はザッパーの線なので、市販ソフトを動かすタイマー方式では使わない。bit5〜7 はオープンバスのまま触らない。
- **手順そのものは未設計**であり、本プロジェクトで新たに決める必要がある。
- **マイク（任意）**: 要求には無いが、『たけしの挑戦状』『ゼルダの伝説』などマイクを使う市販ソフトのために、タイマー方式で 2P ボタン 3 を $4016 D2 に割り当てる設定を用意する案がある。極性が製造時期で逆という記述があるので、押している間は約 10 Hz で 0/1 を切り替える。既定は OFF とし、採否はユーザーに確認する。

#### 1.10.7 特殊形式を使う新規開発ゲームへの注意

- コインのパルス中（上+下）は上下が、スタートを押している間（左+右）は左右が読めない。ゲームは、同時押しを検出したフレームではその軸の入力を無視する。
- NESdev が推奨する「逆方向の同時押しを前のフレームの方向で置き換える」処理を、コインとスタートの検出より前にかけてはならない（検出できなくなる）。
- DPCM を鳴らすゲームでは、読み出しグリッチで「右」が誤検出されることがある。左を押している最中に右が誤検出されると、左右同時（スタート）と誤認される。DPCM を使うゲームは、パッドを 2 回以上読んで一致を確かめるなどの対策をとる（推論）。

## 4. ユーザー要求への影響

### 4.1 タイマー方式（要求 3.3）

- **事実**: PC-10 とファミコンボックスは、時間をハード（BIOS とコインタイマー IC）が管理し、コインをゲームに見せなかった。PC-10 は CPU の停止・リセット、入力・映像・音声のマスクの信号を持ち（MAME の配線、単一出典）、ファミコンボックスは減光・ビープと例外による CPU リセットを持つ（パッドの無効化をコインタイマーが自動で行うかは記載なし）。時間切れの瞬間には打ち切らず、PC-10 は 20 秒（単一出典）、ファミコンボックスは約 1 分（kevtris の観察。警告の時期は資料で食い違い未確認）の猶予を置いた。PC-10 で猶予の後にリセットする点は推論である。市販ソフトは上下・左右の同時押しで続行不能になるものがあり、II コンの START で止まるもの（Tetris 2 + Bombliss）もある。
- **実現性（推論）**: 実現できる。追加の部品は、2A03 /RES と 2C02 /RST を入出力マイコンから操作する線、映像の減光と音声のミュートの仕組み、残り時間を出す手段である。
- **時間切れの扱いの選択肢（推論）**:

| 案 | 内容 | 長所 | 短所・リスク |
|---|---|---|---|
| A. 入力停止のみ | 時間切れで入力を止め、リセットしない（要求 3.6 の仮の読み方） | 単純。前の客が戻れば続けられる | 次の客が前の客の場面から始まる。客がいないのにゲームが動き続ける |
| B. 猶予のあとリセット | 警告 → 猶予（減光・ミュート・入力マスク）→ リセット保持 → 待機画面 | 先例と同じ。次の客は必ず最初から始まる | 猶予中もゲームが裏で動く（実チップでは CPU を止められるか未確認） |
| C. 即リセット | 0 秒で即座にリセット | 最も単純 | 追加コインで続ける機会が無く、客の不満が大きい。先例にない |

- **推奨（推論）**: **案 B を既定とし、案 A を設定で選べるようにする。** 理由は、任天堂の 2 つの先例が共通して採った方式で客に分かりやすく、次の客の始まりがそろうからである。エミュレーション構成では猶予中にエミュレータを一時停止し、PC-10 と同じ「止めて待つ」動作にする。要求 3.6 の「リセットしない」という読みはユーザー確認が要る。
- **残り時間の表示（推論）**: 映像をマイコンが作り直す構成なら、画面への重ね描きとビープを既定にする。部品を増やさずに済む。外付けの 7 セグ・LED は、部品点数を減らす方針に反するので、コネクタだけを任意で用意する程度に留める。
- **2P スタート → I コンの SELECT**: 市販ソフトのタイトル画面のメニュー操作に必要で、PC-10 の筐体（P2 の SELECT/START を P1 の線につなぐ）や JAMMA 化先例の悩み（JAMMA に SELECT が無い）とも合う。要求どおりで問題は無い。
- **法的影響**: 下の 4.5 を参照。技術的に作れても、市販ソフトを営業に使うには権利者の許諾が要る。

### 4.2 通常方式・デフォルト形式（要求 3.4）

- **事実**: 1 フレーム幅のパルスでは取りこぼすゲームがある。VS. の実機は 40〜70 ms。多くのゲームは押下のエッジで反応する。HVC-001 の II コンには SELECT / START のビットが存在しない。
- **影響（推論）**: コイン → SELECT は、整形パルス（ラッチ 4 回以上かつ 67 ms 以上、解放も同じ）と待ち行列（上限 15）で出す必要がある。2P 側の START / SELECT は、AV ファミコン・NES と同じく実ビットを出せば、新規開発ゲームから読める。ゲームが START を C ボタンの代わりに使うのは、新規開発ゲームなら問題ない。
- **推奨（推論）**: 1.10.2 の値を既定値とし、設定画面から押下時間と解放時間を変えられるようにする。新規開発ゲームの開発者向けに「コインは SELECT のエッジで数えること、1 枚ごとに必ず解放期間がある」ことを仕様として示す。

### 4.3 通常方式・特殊形式（要求 3.5）

- **事実**: 正常なレバーは上下・左右を同時に閉じられないが、NESdev は摩耗したパッドや非標準コントローラでは起こり得るとしている。DPCM 読み出しグリッチで「右」が誤検出されることがある。市販ソフトでは同時押しが重大なグリッチを起こす。
- **影響（推論）**: 特殊形式は新規開発ゲーム専用であり、市販ソフトで選ばれると危険である。新規開発ゲーム側は、同時押しを検出したフレームでその軸を無視する、逆方向の除去処理を検出より後にかける、DPCM 使用時に読み直すなどの対策が要る。
- **推奨（推論）**: 特殊形式を選んだまま市販ソフトを動かさないよう、設定画面に注意を表示する。可能なら、新規開発ゲームが通信手順（1.10.6）で基板に「特殊形式で動く」と申告したときだけ特殊形式を有効にする（申告が無ければデフォルト形式で動く）。これで誤設定による市販ソフトの事故を防げる。

### 4.4 ソフトウェアでの切り替え（要求 4）

- **事実**: VS. システムは DIP やコインを $4016/$4017 のビットで読ませていた。多くのゲームが $4016 D1 を D0 と OR して読む。$4017 D3/D4 はザッパーの線である。
- **影響（推論）**: 読み方 A（基板の設定として切り替える）は、テストスイッチ（ピン 15）の設定画面と USB Type-C からの書き換えで実現できる。読み方 B（新規開発ゲームから切り替える）は、OUT1・OUT2 と D1〜D4 で実現できるが、D1〜D4 を常時ドライブすると市販ソフトの入力を壊す。
- **推奨（推論）**: 方式・形式・時間などの設定は不揮発メモリに保存し、物理 DIP スイッチは設けない（部品点数を減らす方針に合う）。ゲームとの通信は、ゲーム側が OUT1・OUT2 で決まった手順を送ってきたときだけ D1〜D4 を使い、それ以外の時は「押されていない」状態に固定する。タイマー方式の中では、ゲームからの切り替え要求を受け付けない（店舗の設定を客が変えられないようにする）。

### 4.5 「市販ソフトはタイマーで動かす」（要求 3.1 の最後の段落）

- **事実**: 著作権法 22 条の2 と 38 条 1 項により、料金を取る営業で家庭用ソフトを客に遊ばせると、許諾が無い限り上映権侵害のリスクが高い。2018 年にゲームバー 4 店舗の 4 名、2011 年に神戸のホテル経営者が逮捕された。任天堂は営利目的の利用許諾を受け付けていない。家庭用ソフトの業務利用ライセンスの公開窓口は見つからなかった。
- **選択肢（推論）**:

| 案 | 内容 | リスク | 費用・手間 |
|---|---|---|---|
| A. 要求どおり、市販ソフトを営業で動かす | タイマー方式を市販ソフト用として運用・宣伝する | 上映権侵害の刑事・民事リスクが高い。販売者も助長と見られ得る | 許諾を取る手間（窓口が見つからない） |
| B. タイマー方式は機能として残し、用途を「権利者の許諾を得たソフト／自作ソフト用」と説明する | 技術仕様は変えない | 運用者が許諾の無いソフトを営業に使えば A と同じ。販売者のリスクは下がる | 説明書・宣伝の文言のみ |
| C. タイマー方式を新規開発ゲームにも使えるようにする | 新規開発ゲームでも時間制で営業できる | 上映権の問題は生じない | タイマー方式は入力を素通しするので、追加の手間はほぼ無い |

- **推奨（推論）**: **B と C を組み合わせる。** タイマー方式の機能はそのまま作るが、説明書と宣伝では「市販カート向け」と書かず、「権利者の許諾を得たソフトまたは自作ソフト用」と説明する。営業で動かすソフトは新規開発ゲームか許諾済みのタイトルに限るよう、ユーザーに注意を伝える。これは法的助言ではなく、実際に営業に使う前に弁護士と権利者に確認する必要がある。

### 4.6 設置・販売にかかわる要求（要求 1・2 全般）

- **風営法（推論）**: 基板はどの方式でも規則 3 条 2 号のテレビゲーム機に当たり得る。ファームウェアに景品払出し、得点に応じた出力、得点やクレジットの持ち帰り（QR コード、パスワード、カード書込み）を実装しない。料金と時間の設定は 5 号営業では法令上自由なので、設定範囲を制限する必要は無い。
- **CPU / PPU の移植（要求 2）と古物営業法（推論）**: 中古本体を買い集めて外したチップを載せた基板を販売するなら、古物商許可を取るのが安全側である。自分の筐体だけで使うなら不要の余地がある。設計に直接の影響は無いが、事業の形を決める前に確認する。
- **電源と PSE（推論）**: 基板は JAMMA 端子から +5V/+12V を受けるので、基板単体の販売に PSE は不要と考えられる。USB Type-C 端子はファームウェア更新用で、AC の USB 充電器を同梱して売るならそれは直流電源装置（◇PSE）に当たる。同梱しなければ問題は生じない。
- **Pico の選択と電波法（推論）**: 無線の無い Pico 2 を使えば電波法は無関係。Pico 2 W を使う場合は認証済みのまま無改造で実装する。複数枚のマイコンを使う構成（要求 5）でも、すべて Pico 2 にすれば論点は生じない。要求 5 は Pico 以外の Raspberry Pi も認めるが、無線付きの他の Raspberry Pi の日本の認証は本シートの調査範囲外で未確認である。
- **PL 法（推論）**: 販売者は製造業者になる。JAMMA エッジの逆挿入防止、ヒューズやポリスイッチ、カウンタ・ロックアウトのドライバ出力の短絡保護（ポリスイッチか 1〜2 Ω の直列抵抗）を基板に入れる。
- **商標（推論）**: 基板の名前やシルク印刷に「ファミコン」「Famicom」「ファミリーコンピュータ」を使わず、「HVC-001 用 60ピンカートリッジ対応」のように書く。

### 4.7 マイコンの枚数と将来の更新（要求 5）、USB Type-C（要求 6）

- **影響（推論）**: コイン・タイマー・入力の処理は、映像や CPU/PPU のエミュレーションと時間の制約が異なるので、専用の入出力マイコンに分けると設計が素直になる。入出力マイコンが持つべき線は次のとおり（本シート作成者の数え上げ）。
  - JAMMA 側の入力: 1P のレバー 4 本・ボタン 4 本・スタートで 9 本、2P も 9 本、コイン 1・コイン 2・サービス・テスト・ティルトで 5 本、合計 23 本。
  - JAMMA 側の出力: カウンタ 1・2、ロックアウト 1・2 の 4 本（ドライバ経由）。
  - ファミコン側: OUT0・OUT1・OUT2、/OE1・/OE2、$4016 D0・D1・D2、$4017 D0〜D4 の 13 本。電圧の違うチップをつなぐためのレベル変換が要る（詳細は本シートの範囲外）。
  - 制御: 2A03 /RES、2C02 /RST、映像の減光、音声のミュート、映像マイコンへの重ね描き指示。
- **推奨（推論）**: 入出力マイコンを独立させ、タイマーの状態（残り時間、方式、設定）はこの 1 枚だけが持つ。映像マイコンには表示内容だけを渡す。ファミコン側の 13 本は拡張用コネクタにも引き出し、将来 CPU/PPU を差し替えたときも同じ入出力マイコンを使えるようにする。要求 5 の「各種メモリのアップデート」はコイン・タイマーの仕組みに直接は関係しないが、エミュレーション構成でメモリや性能を拡張しても、パッドの見え方（$4016/$4017 と OUT0〜2）を変えなければ本シートの 3 方式はそのまま使える。設定の書き換えとファームウェア更新は、同じ USB Type-C 端子から行う（要求 6）。マイコンが複数枚になっても端子は 1 つにまとめ、入出力マイコンのファームウェアもその端子から更新できるようにする（要求 6.2 の方針と同じ）。なお、要求 2 の「ラズパイを挿すか CPU/PPU を挿すかを DIP スイッチ等で設定する」選択は、本シートが扱う方式・形式の切り替え（ソフトウェア）とは別の設定であり、ここで物理 DIP を設けないとした判断には含めない。
