# ファミコン本体ハードウェア（RP2A03・RP2C02・周辺回路・カセット端子・コントローラ） - リファレンスシート

- RP2A03（CPU）、RP2C02（PPU）、60ピンカセット端子、15ピン拡張端子、74139・74373・74368 の配線は、4種類の独立したネットリストと NESdev の逐語図で全ピンが一致した。第1次調査の表はほぼ正しく、訂正は細部（マイク経路、$4016 のオープンバス範囲、基板版ごとの差）に限られる。
- 新しい基板は、21.47727 MHz の CMOS 発振器から CPU・PPU に直結でクロックを与え、PPU /RST は +5V 固定（ファミコン方式）、CPU /RST は PPU より 12 ms 以上遅らせて解除する。メモリは 62256 の上位アドレスを GND に固定して代用でき、WRAM /CS の遅延回路と PPU /CS のコンデンサは省略できる。
- カセット端子の CPU D0〜D7 にはスロット直近に 33〜100 Ω の直列抵抗を入れ、データバスにプルアップは付けない。CPU・PPU の出力は TTL しきい値の 5V ロジック（74HCT・AHCT・LS・ALS）か、3.3V 電源の 74LVC で受ける。
- コントローラの読み出しは「OUT0 でラッチ、/OE1・/OE2 の間だけ M2 の反転をクロックとして出す、368 で反転して D0 に乗せる」方式である。$4016 は D0〜D2 しか駆動せず、D3〜D7 はオープンバスのまま残す必要がある（Paperboy など Mindscape 製ソフトが $40/$41 に依存する）。
- 上下・左右の同時押しは多くの市販ソフトでグリッチを起こすので、市販ソフトを動かすタイマー方式では決して合成しない。特殊形式（同時押しをコイン・スタートに使う）は新規開発ソフト専用である。
- データの日付: 2026-11-10

## 1. 確定事実

### 1.0 この章の読み方と用語

- 信頼度の印は次のとおりとする。**確認済**＝独立した2つ以上の出典、またはネットリスト・データシート・実測値で確認できたもの。**単一出典**＝出典が1つだけのもの。**未確認**＝出典の間で食い違う、または資料が見つからないもの。
- 「ネットリスト」とは、基板設計データの中で、どの部品のどのピンがどのピンとつながっているかを示す一覧である。本シートで使ったネットリストは、OpenFC（HVC-CPU-07 の再現 KiCad データ）、TrexMakes（HVC-CPU-GPM-02 と HVC-CPU-07 の KiCad データ）、OpenTendo（NES 用再現データ）、TinyNES（実チップを使う量産小型 NES の Eagle データ）である。HVC-CPU-05 については BABAX 氏の実機トレース回路図（Rev.07）を使った。
- 「HVC-CPU-05」「HVC-CPU-07」「HVC-CPU-GPM-02」はファミコン（HVC-001）のメイン基板の版名である。本シートで「05/07」と書くときは前期の標準的な基板、「GPM-02」と書くときは 1989 年の後期基板を指す。
- 「/」で始まる信号名（/RST など）は、Low のときに有効になる信号（負論理）を表す。
- 「M2」は RP2A03 が出す CPU サイクルのクロック出力で、φ2（6502 内部の第2相クロック）から作られる。
- 「オープンバス」とは、どの回路も駆動していないデータ線を読んだとき、直前にバス上にあった値がそのまま読める現象である。

**PPU /RST（pin 22）が何をリセットするか**（確認済: NESdev 逐語、ネット3件）

- チップの一部を電源投入時の状態に戻す。対象は、クロック分周器、映像位相の生成回路、走査線・画素カウンタ、偶数/奇数フレームの切り替えフラグである。
- さらに次のレジスタを 1 フレームの間ゼロに保つ。PPUCTRL、PPUMASK（$2001）、PPUSCROLL（$2005。VRAM アドレスラッチ「T」、細かい X スクロール、H/V トグル）、VRAM 読み出しバッファ。
- ファミコンはこのピンを +5V に直結している。そのためリセットボタンを押している間も画面が消えない。NES の前面ロード機はリセットボタンで CPU と PPU の両方をリセットし、ファミコンと NES-101 は CPU だけをリセットする。
- PPU のクロック分周器がリセットされるので、PPU をリセットすると CPU と PPU のサブサイクルの位相関係が変わる。PPU リセット後の最初の描画フレームでは OAM（スプライト属性メモリ）が壊れやすい。（単一出典: NESdev ユーザーページ Fiskbit）
- リセット後およそ 29658 CPU クロックより前に PPUCTRL、PPUMASK、PPUSCROLL、PPUADDR へ書いても無視される。PPUSTATUS、OAMADDR、OAMDATA（$2004）、PPUDATA、OAMDMA（$4014）はすぐ使える。VBL フラグ（PPUSTATUS bit7）は電源投入時に不定で、リセットでは変わらず、次は約 27384、その次は約 57165 CPU クロックで立つ。（単一出典: NESdev PPU power up state）
- 電源を切って 20 秒未満で入れ直すと、リセットと同じくレジスタ書き込みが無視され、レジスタ初期値も変わる。（単一出典: 同上）

ピンごとの補足:

- **pin 18・48**: CIRAM は本体の 2KB の VRAM のことである。カセットが CIRAM /CE（通常は /PA13 をつなぐ）と CIRAM A10（PA10 か PA11 をつなぐ）を決め、ネームテーブルのミラーリングを選ぶ。本体側では pin 18 が VRAM の A10（SRAM pin 19）、pin 48 が VRAM の /CS（SRAM pin 18）に直結している。（確認済）
- **pin 19〜25・50**: 74373 の出力（PA0〜PA7）である。pin 25…19 = PA0…PA6、pin 50 = PA7。（確認済）
- **pin 31**: 一部の RF モジュレータ基板の版では TV/GAME 切替にだけつながり、カセットが pin 30 と 31 を短絡したときだけ映像が出る。他の版では普通の +5V である。OpenFC（07）では別系統の VCC2（C24 470µF と電源コネクタ P3.4）、TrexMakes 07 では +5VA、TrexMakes GPM-02 では pin 30 と同じ +5V である。（確認済）
- **pin 44**: 74139 pin 9（2Y3）の出力。M2 と A15 の NAND で、$8000〜$FFFF の M2 High 期間に Low になる。（確認済）
- **pin 45・46**: pin 45 は本体→カセットで、2A03 の音声を増幅したもの（368 の音声アンプ出力）。pin 46 はカセット→本体で、本体の音声出力（RF モジュレータ）へ行く。カセット内で 45 と 46 がつながっていないと音が出ない。拡張音源を持つカセットは、ここで自分の音を混ぜて返す。（確認済）
- **pin 49**: PPU PA13 を 368 の空きゲートで反転したもの。（確認済）

### 1.7 コントローラ

#### 1.7.1 読み出し手順

1. ソフトが $4016 に 1 を書く。OUT0 が High になり、両方のパッドの 4021（8ビットの並列入力・直列出力シフトレジスタ）が、8個のボタンの状態を取り込み続ける。この間 $4016/$4017 を読むと、何度読んでも A ボタンの状態が返る。（確認済）
2. ソフトが $4016 に 0 を書く。OUT0 が Low になり、その時点の状態が確定する。（確認済）
3. ソフトが $4016（パッド I）または $4017（パッド II）を読むたびに、368 が /OE の間だけ M2 を反転してパッドのクロック線に出す。読み出し中はクロックが Low で、読み終わると High に戻り、その立上りで 4021 が1ビットシフトする。（確認済）
4. 報告順は 0 = A、1 = B、2 = Select、3 = Start、4 = Up、5 = Down、6 = Left、7 = Right。（確認済）
5. 8回読んだ後は、公式のコントローラは 1 を返し続ける。4021 の SER（直列入力）が GND なので空いたビットに 0 が入り、368 で反転されて 1 になる。（確認済）
6. 4021 の P/S が High の間、並列入力は非同期に取り込まれる（「parallel entry is asynchronous」）。（確認済: TI CD4021B データシート）

- **DPCM 読み出しグリッチ**: DPCM（音源の1チャンネル）の DMA が $4016/$4017 の読み出しと同じサイクルに起きると、クロックが余分に入ってビットが1つ欠ける。典型的には「右」が押されたように誤検出される。PAL の 2A07 で修正されたが、NTSC の 2A03 は影響を受ける。（確認済: NESdev Controller reading と CPU variants）

| 7 | PI-1 | RIGHT | RIGHT | 確認済 |

- 各ボタン入力は印刷カーボン抵抗でプルアップされ、ボタンで GND に落ちる。値は資料によって違う: 第1次調査（05 回路図）はパッド I 50k、パッド II 43k、OpenFC は 40k、TrexMakes のパッド II は 33k。印刷抵抗なので個体差が大きい。（未確認。値は個体差）

#### 1.7.4 II コンの SELECT/START の扱い

- 初代ファミコンの本体直結 II コンには SELECT と START のボタンがない。4021 の PI-6・PI-5 が +5V に固定され、そのビットは常に 0（押されていない）と読める。（確認済: NESdev 逐語とパッドのネット2件）
- NESdev は「Famicom games must not rely on the second player being able to push Start or Select.」と書いている。（単一出典: NESdev Standard controller）
- AV ファミコンは II コンにも SELECT/START があり、マイクはない。NES も 2P 側に SELECT/START がある。（単一出典: NESdev Standard controller）
- Tetris 2 + Bombliss は、2P が START を押すとソフトロック（操作不能）になる（NES、AV ファミコン、拡張端子のコントローラ使用時）。（単一出典: NESdev Game bugs）
- 業務用の先例: PlayChoice-10 は P2 の Select/Start を P1 の線に配線している。VS. System はスタートボタンをシフトの3番目のビット（家庭用の Select の位置）に入れ、UniSystem では Start の位置（0x08）が未使用である。（確認済: MAME と NESdev の一致）

### 1.9 周辺回路の部品定数と基板リビジョンによる違い

#### 1.9.1 音声回路（HVC-CPU-05/07）

信頼度: 確認済（HVC-CPU-05 回路図の目視、OpenFC と TrexMakes 07 のネット）。参照番号 R1/R2 は版によって入れ替わる。

| 部分 | 定数と接続 |
|---|---|
| AD1（pin 1、矩形波） | 100 Ω で GND へ。20k で加算点へ |
| AD2（pin 2、三角波・ノイズ・DPCM） | 100 Ω で GND へ。12k で加算点へ |
| マイク | MIC IN が2つに分岐する。(a) R3 10k → 音声加算点。(b) R8 10k → U7 pin 10（1A4）、ここに 0.1 µF（05 は C10、OpenFC は C7）を GND へ → pin 9 → CPU D2 |
| 結合 | 加算点 → C2 1 µF/50V → U7 pin 14（2A2） |
| 増幅 | 368 の空きゲート（2A2 → 2Y2）を反転増幅器として使う。帰還 R7 100k（pin 13 と 14 の間） |
| 出力 | U7 pin 13 = カセット pin 45 = 拡張 pin 2。出力に C8 0.1 µF/12V を GND へ |
| カセットからの戻り | カセット pin 46 → 電源/RF 基板（R13 12k、C18 0.001µF を経て RF-M AUDIO） |

- 利得は帰還/入力比から矩形波で約 5 倍（100k/20k）、TND（三角・ノイズ・DPCM）で約 8.3 倍（100k/12k）と見積もれるが、100 Ω の負荷があるので実効値は違う。（推論。未計算）
- 拡張音源の音量比（2A03 の矩形波との比）: FDS は最大で矩形波の約 2.4 倍、VRC6 の矩形波は 2A03 の矩形波とほぼ同じ（位相は反転）、MMC5 は対応する APU チャンネルと同じ（MMC5 の DAC は 15kΩ 以上を駆動すべき）、N163 はゲームにより 11.2〜18.0 dB 大きい（Final Lap 12.7、Rolling Thunder 16.9、King of Kings 18.0 ほか）。（単一出典: NESdev 各音源ページ）
- AV ファミコンは旧ファミコンより音量がやや小さい。（単一出典: Nerdly Pleasures）

- Balloon Fight のゲームオーバー曲は、最後の音でノイズチャンネルにゴミデータを書き込み、それが偶然、文字付きの CPU（E/G/H）にしかない周期（tonal）モードを有効にする。そのため無印 CPU と文字付き CPU で鳴り方が変わる。（単一出典: NESdev Game bugs。原文を確認済み）
- VS. 基板で 2A03G に替えると TKO Boxing が動かないという伝聞がある（KLOV 伝聞）。（単一出典）
- 中国ルートの「RP2A03E」が実は 16 分周（2A07 相当）の偽物だった例がある。（単一出典）
- 互換品 UA6527（CPU）は矩形波のデューティが入れ替わっている。UA6528（PPU）が全ゲーム互換かは不明。UA6527P の一部ロットと TA-03N には「Runs hot」の記載がある。（単一出典: OpenTendo BOM、NESdev CPU variants）

#### 1.10.2 RP2C02 のリビジョン

| 版 | 特徴 | 信頼度 |
|---|---|---|
| 無印 / A / B | X = 255 のスプライト誤表示。2C02A は $2001 への書き込みで描画が乱れる、PPU バスの書き込みタイミングが後の版と違い Everdrive Pro などの現代のカセットで画面が化ける、「Some modern PCBs generate almost exclusively glitchy pattern fetches」 | 確認済（NESdev PPU variants と Fiskbit） |

#### 1.11.6 3.3V ロジックとの接続

| 経路 | ルール | 信頼度 |
|---|---|---|
| 3.3V CMOS → 2A03/2C02 の入力（CLK、/RST、/NMI、/IRQ） | 直結で可。ただしデータバスや PPU のレジスタ選択を 3.3V で駆動した量産例はないので、データバスに書き込むなら 5V 側に 74HCT245 などを置く | 直結可は確認済（TTL しきい値の発言と実験）。データバスは推論 |
| 2A03/2C02 の出力 → 5V ロジック | 74HCT / 74AHCT / 74LS / 74ALS で受ける（VOH の保証が 2.4V のため）。74HC は実績はあるが余裕が小さい | 推論（根拠は 1.10.5） |
| 2A03/2C02 の出力 → RP2350（3.3V） | 5V トレラントの条件（IOVDD 通電中）を守るか、3.3V 電源の 74LVC（5V 入力許容）で受ける（NESdev 推奨方式）。マイコンが起動していないときに 5V が直接 GPIO に掛からないようにする | 推論（根拠は 1.10.5） |
| 3.3V → カセット（5V CMOS のマッパー入力） | 5V の CMOS 入力の VIH は典型 3.7V なので、3.3V 出力では足りない。5V 電源の TTL 入力型バッファ（74HCT245 など）を挟む | 推論（根拠は NESdev Implementing Mappers In Hardware） |
| PPU /INT（オープンドレイン） | プルアップ先は 5V。マイコンで監視するなら LVC バッファ経由 | 推論 |
| PPU の AD バスや ALE をマイコンで読む場合 | PPU の負荷を増やさないよう、74LVC245 など1個に集約してから取り込む | 推論 |
| 先例 | krzysiobal のフラッシュカセットは EPM240 CPLD と 74LVC245 で 5V バスと 3.3V 側を変換している | 単一出典 |

#### 1.11.7 電源の予算

- +5V 系の予算は、CPU・PPU・RAM・ロジック・カセットで 0.5 A、余裕を含めて 1 A 以上とし、そこにマイコンと映像変換回路を足す。（推論。根拠は 1.10.4 の 0.35〜0.5 A の実測）
- 基板上の +5V を 4.75〜5.25V に保つ。JAMMA の +5V は配線で電圧が下がるので、基板上で 5.0V 付近になるよう調整する。（推論）
- JAMMA 筐体は安定化 +5V を出すので、7805 は載せない。（推論）
- CPU・PPU に通常ヒートシンクは要らないが、閉じた筐体で連続運転するので PPU 上の通風を確保し、熱で不安定なドナーには後付けできるようにする。（推論）

取り外しと検査の手順（推論）:

1. ドナー基板は廃棄前提なので、チップを優先して守る。デソルダリングガンで1ピンずつ吸い、吸えなかったピンははんだを足して再吸引する。どうしても抜けなければ基板側のランドごと切り離す。リードの切断はチップを再使用できなくするので避ける。GND ピン（CPU pin 20 / PPU pin 20）は熱が逃げるので温度を上げる。
2. 外観確認（ピン曲がり、腐食、刻印でリビジョンを確認）。
3. 新基板のソケットに挿し、電源電流を見ながら投入する。
4. CPU 単体で M2 = CLK/12、デューティ 15/24（E/G/H）を確認する。無印は 17/24、偽物は ÷16。
5. 音だけ鳴るテスト ROM で APU を確認する。
6. 画面テスト（CPU/PPU テスト ROM）と長時間の熱ランで PPU を確認する。

### 3.2 資料が見つからない事項

- RP2A03 / RP2C02 単体の消費電流（ICC）とパッケージ熱抵抗。
- 2A03 の /IRQ・/NMI の内部プルアップの有無と値。/RST の内部プルアップの抵抗値相当。
- RP2C02 の入力しきい値。CLK 入力の VIH/VIL、入力容量、許容デューティ範囲。出力駆動能力（IOH/IOL）。
- 不正確なデューティ比が PPU のデジタル動作に与える影響。
- TC40H368 の公式データシート。
- 任天堂純正の 60 ピンスロットのメーカー・型番。WingTAT S-60M-2.54-5、ヒロセ CR22A-60D-2.54DS(70)、LCSC の ED60BGFBK・EC60P03BK の適合板厚と接点位置。
- カセットのシェル（外装）寸法。
- VOUT の無負荷電圧。
- 大電流カセット（フラッシュカセットなど）と FDS RAM アダプタの電流値・スロット要件。
- PPU を本体から離して配線した基板での具体的な不具合報告。
- ドナーチップの故障率と故障モード。
- 2A03 のクロックを止めてよい時間（6502 のダイナミック回路の保持時間）。10kHz まで「安全」という発言はあるが、完全停止の可否は未確認。
- PlayChoice-10 の /GAMESTOP が実機で何を操作していたか。
- II コンの SELECT/START ビットを読むファミコンソフトの具体名。同時押しでクラッシュする市販ソフトの網羅的な一覧。
- RP2350 の 5V トレラント条件と E9 エラッタの正確な内容（データシートで要確認。電源・マイコン系シートの範囲）。
- JLCPCB での 74HCT 系・62256 系（IS62C256AL など）の分類と在庫（部品系シートで要確認）。74HC14・74HC139・74HC373・74HC368 の分類は parts_class_reverification.md で確認済み（1.11.3 節）。
- カセット寸法表の D.1・D.2 の起点「card edge base」の意味（1.3.3 節）。

### 3.3 実機（試作基板）で確かめるべきこと

1. **クロックの直結**: 選んだ CMOS 発振器（5V または 3.3V、DC 結合、22〜33 Ω 直列）で、手持ちのドナー CPU・PPU（E 系と G 系の両方）が起動するか。M2 = CLK/12 とデューティ 15/24 をオシロで確認する。
2. **リセットの順序**: PPU /RST 固定・CPU /RST 遅延の構成で、Magic John または The Lord of King が電源投入から起動するか。遅延時間（12 ms・20 ms・50 ms）を変えて確かめる。
3. **OAM 破損**: 2C02G-0 ドナーで、CPU D0〜D7 の直列抵抗あり（33 Ω・100 Ω）・なし（0 Ω）を比べる。フラッシュカセット（Everdrive など）でスプライト化けが出ないか。
4. **3.3V 側との接続**: マイコンから 3.3V で /RST、/NMI 監視、OUT0 読み取り、$4016/$4017 応答を行ったとき、論理レベルの余裕をオシロで確認する。
5. **消費電流**: 電源ラインに直列抵抗を入れ、CPU・PPU をソケットから抜き差しして差分を測る。JAMMA 筐体の +5V の基板上の電圧も測る。
6. **熱**: 筐体内で長時間運転し、PPU の温度とスプライトの崩れを確認する。
7. **カセットスロット**: 候補のコネクタで実際のカセット（1.2 mm 厚）の保持力と接触を確認する。シェルが基板上の部品に当たらないか、実物で測る。
8. **ピン番号**: 試作基板のフットプリントで、pin 1（正面側の列の左端）と pin 31（その真後ろ）が正しいことを、市販カセットの導通で確認する。
9. **音声**: pin 45→46 のループで、拡張音源のカセット（N163、VRC6 など）の音量差を測り、トリマの範囲を決める。
10. **映像**: VOUT 配線と VRAM バスの位置関係で縦縞が出ないか確認する（コンポジットを使う場合）。
11. **コントローラ応答**: 4021 相当の応答（ラッチ、8回後の 1、DPCM グリッチ時の余分なクロックへの追従）を、Paperboy（$41 依存）と DPCM を使うソフトで確認する。
12. **ドナーチップの判定**: 刻印でリビジョンを記録し、1.13.2 節の手順で検査する。

## 4. ユーザー要求への影響

この章では、出典のある事実を【事実】、本シートの作成者の判断を【推論】と明記する。

### 4.1 部品選定・実装ルール（1章: JLCPCB の Basic Parts、LCSC 在庫、秋月の手はんだ、部品の種類と点数の削減）

- 【事実】本体のロジックは 74139・74373・368 ×2・2K×8 SRAM ×2 の4種類だけで、2K×8 SRAM は 62256 の上位アドレスを GND にして代用できる（TinyNES の量産実績）。WRAM /CS 遅延回路（ダイオード・抵抗・コンデンサ）と PPU /CS の 2個のコンデンサは省略できる。
- 【事実】famicom_electrical_and_pitfalls.md によれば JLCPCB Basic にあるインバータは 74HC14 だけで、74HCT125/244/245 は Extended、74HC373 は C5636、74HC139 は C512773 と記録されている。parts_class_reverification.md の再照会では 74HC14（C5605）が Basic、74HC373（C5636）と 74HC139（C512773）が Extended で一致し、74HC368D（C5635）は Extended で在庫 0 だった。秋月にも 74HC139・74HC368・CD4021・DIP の並列 SRAM の在庫はない（parts_round2_sourcing_and_cost.md）。
- 【推論】選択肢と得失:
  - 案A「純正どおり 368 ×2 を使う」: 回路は実機と同じで安心だが、74HC368 は JLCPCB で Extended・在庫 0、秋月でも在庫 0 で、事実上調達できない。
  - 案B「74HC240 系1個 + 74HC14 + オペアンプ」（TinyNES 方式）: 部品の流通は良いが Extended が増える。
  - 案C「コントローラ応答をマイコンとバッファで作り、368 も 4021 も載せない」: 部品点数は最少。応答のタイミングをファームウェアで保証する必要がある。
- 【推論】推奨: /PA13 は 74HC14 の1ゲートで作り、$4016/$4017 の応答は 3ステートバッファ1個（D0〜D4 だけ駆動、D5〜D7 は駆動しない）とマイコンで作る（4.3 節）。音声増幅はオペアンプにする。Basic で足りない部品（3ステートバッファ、レベル変換、カセットスロット、DIP-40 ソケット）は Extended か秋月の手はんだになる。カセットスロットと DIP-40 丸ピンソケットは手はんだ部品として秋月の在庫を確認する必要があるが、その在庫は本シートの範囲では未確認である。

### 4.2 製品要求（2章: CPU・PPU の移植とエミュレーションの両方、ソケット、どちらかを設定で選ぶ）

- 【事実】移植するチップは RP2A03 と RP2C02 の2個だけで、どちらも DIP-40 である。周辺のロジック（デコーダ、ラッチ、SRAM）は新しい部品で作れる。
- 【事実】ドナーの版によって挙動が違う。無印 CPU、無印/A/B/C の PPU は避けるべきとされ（OpenFC）、2C02G-0 は CPU データ線の反射に弱い。
- 【推論】実チップ側の設計は 1.11 節のルールどおりにする。特に、CPU D0〜D7 の直列抵抗、PPU /RST の固定と CPU /RST の遅延、EXT0〜3 の 10 kΩ、PPU の 10 µF タンタルは必須とする。
- 【推論】エミュレーション（Raspberry Pi）側は、同じカセット端子を 5V で駆動する必要がある。カセットのマッパーは 5V CMOS 入力のことがあり、3.3V 出力では VIH（典型 3.7V）に届かないので、5V 電源の TTL 入力型バッファ（74HCT245 など）を挟む。エミュレーション側は /ROMSEL（M2 と A15 の NAND）、M2 のタイミング（High 期間 349.2 ns 相当）、PPU /A13、CIRAM の扱い（カセットが CIRAM /CE と A10 を返す）を再現する必要がある。
- 【推論】「どちらを挿したか」の設定手段の選択肢:
  - 案A「DIP スイッチ1極またははんだジャンパ」: 確実で安い。設定ミスの余地がある。
  - 案B「マイコンが自動判別する」（例: ソケット上の CPU の M2 が動いているかを見る）: 設定ミスがなくなるが、判別回路とファームウェアが要る。
  - 推奨は案B を主にし、案A を強制設定用に残すことである。両方のモードで、使わない側の出力がバスを駆動しないよう、バッファの /OE で切り離す。
- 【推論】ソケットの共用（同じ DIP-40 ソケットに実チップか代替モジュールを挿す）を選ぶ場合、代替モジュールは 1.1 節・1.2 節の全40ピンを 5V で再現する必要がある。現行要求（5章）ではラズパイを何枚使ってもよいので、GPIO が1枚で足りなければ枚数を増やして解決できる。具体的な割り振りはマイコン系シートで判断する。

### 4.3 動作方式と入力形式（3章: タイマー方式、デフォルト形式、特殊形式）

共通（【事実】に基づく実装条件）:

- 【事実】ソフトはストローブ（OUT0）でラッチし、/OE1・/OE2 の間のクロックで1ビットずつ読む。読み出し順は A、B、SELECT、START、上、下、左、右。8回の後は 1 を返す。$4016 は D0〜D2、$4017 は D0〜D4 だけを駆動し、上位ビットはオープンバスのまま残す。
- 【推論】入力の注入方法の選択肢:
  - 案A「実物の 4021（または 74HC165 系）をパッドごとに置き、並列入力をマイコンが作る」: タイミングは実機と同じになり、DPCM グリッチ時の余分なクロックにも自然に追従する。部品が2〜3個増える（74HC165 はロードの極性が 4021 と逆なので反転が要る）。
  - 案B「マイコン（PIO）が OUT0 と /OE・M2 を見てシフトレジスタを模擬する」: 部品は最少だが、1 CPU サイクル（558.73 ns）以内に次のビットを出す応答速度と、余分なクロックへの正確な追従が必要になる。
  - 推奨は案A。理由は、市販ソフトのタイミング依存（DPCM グリッチ対策の読み直し、$41 依存）を実機と同じ回路で満たせるからである。どちらの案でも、出力は 3ステートで D0（と必要な D1〜D4）だけを駆動し、D5〜D7 は決して駆動しない。
- 【推論】マイコンは OUT0（ラッチ）の立下りを数えて、コインやスタートのパルスの長さを「ラッチ4回以上かつ 67 ms 以上」で保証する（coin_op_round2_details.md の推奨）。OUT0 は 74LVC 経由で読む。

タイマー方式（市販ソフト用）:

- 【事実】市販ソフトは I コンの START でゲーム開始とポーズを、SELECT でタイトル画面の項目選択を行う（任天堂の説明書）。II コンの SELECT/START を頼りにしてはならない（NESdev）。上下・左右の同時押しは多くのソフトでグリッチを起こす（1.12 節）。
- 【推論】要求の割り当て（1P スタート → I コンの START、2P スタート → I コンの SELECT、コインはゲームに渡さない）は、これらの事実と合っており実現できる。特に次の点を守る。
  - 同時押しは決して合成しない。レバーの故障で逆方向が同時に閉じた場合も、NESdev の推奨どおり前の方向で置き換えるか、両方を離した扱いにするのが安全である。
  - II コンの SELECT/START ビットは 0（押されていない）に固定する。2P スタートを II コンの START に出すと、Tetris 2 + Bombliss がソフトロックする。
  - $4016 D1 と $4017 D1〜D4 は 0（未接続の見え方）に保つ。多くのソフトが D0 と D1 を OR するので、ここに状態ビットを出すと入力が化ける。
- 【推論】時間切れの扱いの選択肢（3.7 節で未定とされている部分。なお要求の 3.6 節は、ユーザー未確認の前提として「時間切れは操作を受け付けなくするだけで、ゲームのリセットはしない」と読んでいる。以下の推奨はこの前提と異なるので、採るならユーザーの確認が要る）:
  - 案A「入力を全部 0 にするだけ」: 単純だが、次の客が前の客の場面から始める。
  - 案B「CPU だけをリセットする（PPU はリセットしない）」: ファミコンのリセットボタンと同じ挙動で、互換性が最も高い。画面は直前の内容が残る。
  - 案C「CPU と PPU の両方をリセットして保持し、待機画面を出す」（coin_op_round2_details.md の案）: 画面を完全に作り直せるが、解除時は PPU を先に、CPU を 12 ms 以上遅らせて解除しないと、電源投入と同じ順序にならず Magic John などが起動しない。PPU リセット後の最初のフレームでは OAM が壊れうる。
  - 推奨は「猶予中は入力を 0 にし、猶予後に案C で保持し、再開時は PPU→CPU の順に遅延を付けて解除する」である。CPU のクロックを止める一時停止は、2A03 に共通に使える停止ピンがなく（RDY は E 版だけ）、クロックの完全停止の安全性も未確認なので採らない。
- 【推論】マイク（$4016 D2）を使う市販ソフト（たけしの挑戦状など、進行に必須なものが、爆笑!!人生劇場と 2 を別々に数えて少なくとも5本）は、現行要求ではボタン3・4を使わないので遊べない。追加の割り当て（例: 2P ボタン3 → マイク、押している間 0/1 を交互に出す）を設定項目として残すかは、ユーザーへの確認事項である。

通常方式・デフォルト形式（新規開発ソフト用）:

- 【事実】初代ファミコンの II コンには SELECT/START のビットがないが、AV ファミコンと NES では実ビットがある。
- 【推論】2P 側に START・SELECT の実ビットを出す要求は、AV ファミコン互換の見え方なので問題ない。新規開発ソフトは 2P 側の START/SELECT を読めるが、市販ソフトを動かすタイマー方式では 0 に固定する（上記）。
- 【推論】コイン → SELECT は、パルス幅（2.5〜4 フレーム、40〜70 ms 程度）と連続投入の待ち行列で整形する。整形はマイコンが 4021 の並列入力を操作して行う。

通常方式・特殊形式（新規開発ソフト用）:

- 【事実】上下・左右の同時押しは、正常なレバーでは物理的に作れない入力である。市販ソフトの多くは同時押しでグリッチを起こす（1.12 節）。
- 【推論】特殊形式は新規開発ソフトでしか使えない。市販カセットが挿さっている状態で特殊形式が選ばれていると、スタートを押した瞬間に左右同時押しが送られ、Battletoads のように続行不能になるソフトがある。ファームウェアで「特殊形式はタイマー方式と同時に選べない」「起動時の既定はタイマー方式」とし、特殊形式は新規開発ソフトからの指示（4.4 節）か、担当者の明示的な設定でだけ有効にするのが安全である。
- 【推論】特殊形式では、スタートを押している間は左右が、コインのパルス中は上下が、ゲームから読めなくなる（要求の 3.7 節と同じ）。新規開発ソフト側の作法として設計資料に明記する。

### 4.4 切り替えをソフトウェアで行う（4章）

- 【事実】ゲームから基板へ出せる線は $4016 書き込みの OUT1・OUT2（標準パッドでは未使用）で、APU サイクル（2 CPU サイクル）ごとに更新される。基板からゲームへ返せる線は $4016 D1、$4017 D1〜D4 である。$4016 の D3・D4 はオープンバスであり、$41 依存のソフトがあるので駆動しない方がよい。多くのソフトは D1 を D0 と OR し、$4017 D3/D4 はザッパーの線である。
- 【推論】選択肢:
  - 案A「OUT1・OUT2 に決まった手順のビット列を出したら方式を切り替える」: 追加の配線はない。市販ソフトが偶然同じ列を出すと誤動作するので、十分長い合言葉（例: 数十ビットの固定列）にする必要がある。
  - 案B「新規開発カセットに専用のレジスタ（$4020〜$7FFF の未デコード領域）を置き、基板がそれを監視する」: 確実だが、基板がカセットのバスを監視する回路が要る。
  - 推奨は案A。基板→ゲームの返信は、通常方式のときだけ $4017 D3/D4 に出し、タイマー方式では D1〜D4 をすべて 0 にする。こうすれば市販ソフト（D1 を OR する、ザッパーを読む）に影響しない。返信を出すのは「合言葉を受けた後」に限ると、さらに安全である。
- 【推論】市販ソフトは基板に指示を出せないので、市販ソフトを動かすときはタイマー方式を担当者が設定する（要求の 4.2 節のとおり）。起動時の既定値はタイマー方式とし、新規開発ソフトが合言葉で通常方式に切り替える形にすると、設定ミスで市販ソフトに同時押しが届く事故を防げる。

### 4.5 Raspberry Pi の枚数と将来の更新（5章）

- 【事実】CPU と PPU は DIP-40 ソケットに挿す。PPU のアドレスバスは AD0〜AD7 の多重化で、74373 で下位アドレスを取り出している。SRAM は 62256 で代用でき、未使用の上位アドレスは GND に落としている。
- 【推論】選択肢と推奨:
  - **メモリの将来拡張**: 62256 の A11〜A14 を GND に直結せず、0 Ω 抵抗かはんだジャンパ経由で GND に落とし、拡張コネクタにも引き出す。初期状態はファミコンと同じ 2KB の見え方で、後から上位アドレスを使える。費用は 0 Ω 抵抗8個程度で小さい。
  - **CPU・PPU の差し替え**: DIP-40 丸ピンソケットにし、ソケットの全ピンを拡張コネクタからも触れるようにしておく。代替モジュール（FPGA やマイコン）はソケットに挿すか、拡張コネクタから入れる。CPU と PPU のクロックとリセットは同じ発振器・同じリセット回路から配る構成にし、代替モジュールもそれを受け取れるようにする。
  - **拡張コネクタ**: CPU バス（A0〜A15、D0〜D7、R/W、M2、/IRQ、/NMI）、PPU バス（AD0〜AD7、PA8〜PA13、ALE、/RD、/WR）、音声（pin 45 と 46）、映像（VOUT）、OUT0〜2、/OE1・/OE2 を引き出す。CPU データバスの直列抵抗の位置（スロット直近）を崩さないよう、拡張コネクタはスロットから見て抵抗の CPU 側から取る。
  - **マイコンを役割ごとに複数枚にする**: 5V バスの読み取りは 3.3V 電源の 74LVC で受け、マイコンから CPU・PPU の入力（/RST、/NMI、CLK を作る場合）へは 3.3V 直結で足りる。データバスへ書き込むマイコンは 5V 側に 74HCT245 を置く。
- 【推論】PPU の AD バスと ALE を映像変換用のマイコンで読む場合は、PPU の負荷を増やさないよう 74LVC245 など1個にまとめてから取り込む。

### 4.6 USB Type-C によるファームウェア更新（6章）

- 【事実】本シートの範囲（ファミコン本体のハードウェア）には、USB に関わる事実はない。関係するのは電源だけで、CPU・PPU・RAM・ロジック・カセットで 0.35〜0.5 A を見込む。
- 【推論】USB 接続中に、USB の VBUS がファミコン側の +5V（カセットを含む）に流れ込むと、USB ホストの電流制限を超えるおそれがある。USB の VBUS は書き込み用のマイコンだけに給電し、基板全体の +5V とはダイオードなどで分けるのが安全である。詳しくは電源・マイコン系シートで扱う。
- 【推論】マイコンを複数枚にする場合（5章）も、Type-C 端子は1つにまとめ、端子につながる1枚が他の枚を書き換えるか USB ハブ IC を置く（要求の 6.2 節）。ファミコン側から見た制約は、更新中もソケット上の CPU を /RST で止めておくことと、更新中にカセット端子・CPU バスをマイコンが駆動しないよう、バッファの /OE で切り離しておくことである。
- 【推論】CPU・PPU・メモリを将来差し替える場合（5章）、代替モジュール側のファームウェアも同じ Type-C 端子から更新できるよう、拡張コネクタに USB（または書き込み用の UART/SWD）の線を引き出しておく。

### 4.7 ほかの章とまたがる注意（推論）

- 映像は 15.7458 kHz / 60.0988 Hz なので JAMMA の 15 kHz モニタの範囲に入ると見込まれるが、モニタ側の許容範囲は映像系シートで確認する。
- 音声は pin 45→46 のループを JAMMA のスピーカアンプへ送り、拡張音源の音量差はアンプ手前のトリマで調整する。

### 6.3 確認できなかったこと
