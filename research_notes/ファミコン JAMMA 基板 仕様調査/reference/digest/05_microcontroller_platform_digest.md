# マイコン基盤（Raspberry Pi Pico 2 / RP2350）とエミュレーション方式 - 要約

データの日付: 2026-11-10（秋月電子の価格・在庫、GitHub のリリース、データシートの版はすべてこの日に取得した値）。

この要約で使う言葉を先に定義する。

- **実チップモード**: ファミコン本体から外した CPU（RP2A03）と PPU（RP2C02）を基板のソケットに挿して動かす方式。
- **エミュレーションモード**: CPU と PPU をマイコンのソフトウェアで再現（エミュレート）する方式。
- **ダンプ方式**: エミュレーションモードで、電源投入時にカセットの ROM の中身をマイコンのメモリへ読み出し（ダンプし）、その後はメモリ上のデータで動かす方式。
- **マッパー**: カセットに載っている、ROM のバンク切り替えなどを行う回路。iNES 規格の番号（mapper 0, 1, 4 など）で区別する。
- **GPIO**: マイコンの汎用入出力端子。**FT ピン**は RP2350 のデータシートで「Fault Tolerant」と分類される GPIO で、条件付きで 5.5V まで耐える。**IOVDD** は GPIO 用の電源（Pico 2 では基板上の 3.3V）。
- **PIO**: RP2350 が持つ、端子を 1 クロック単位で操作できる小さなプログラム実行装置。
- **BOOTSEL / UF2**: BOOTSEL は押しながら電源を入れると USB 書き込みモードになるボタン。UF2 はそのとき見えるドライブにファイルを置くだけで書き込めるファームウェア形式。
- **A/B 区画・TBYB**: RP2350 のブート ROM の機能。フラッシュの 2 つの区画を交互に更新し、新しいイメージが自己テストに合格しない限り旧イメージに戻す。
- **Basic / Extended**: JLCPCB の部品分類。要求では PCBA は Basic 部品のみとしている。
- 確度の語: 確認済 = 独立した出典 2 つ以上、またはデータシートや実データで確かめたもの。単一出典 = 出典が 1 つだけ。未確認 = 出典で確かめられていないもの（計算値を含む）。推論 = 調査者の判断。

## 1. この分野の結論

1. マイコンは RP2350（秋月の Raspberry Pi Pico 2、販売コード 129604、¥990、在庫 1,462）を使い、Linux が動く Raspberry Pi は端子不足・起動の遅さ・電源断への弱さから採らない。（確認済の事実にもとづく推論）
2. エミュレーションモードは、ダンプ方式なら Pico 2 1 枚・22 本の端子で組める見込みで、日本のライセンス品カセット 881 本が使う 58 種のマッパーはすべて既存エミュレータ pico-infonesPlus に登録済みである。（マッパーの登録は確認済、端子 22 本は机上の割り当てで未確認）
3. ただし登録はそのまま完全動作を意味せず、pico-infonesPlus は定格 150 MHz を超える 252 MHz で動かしており、定格で全速が出るかは未確認である。また 15kHz アナログ RGB とカセット読み出しの両方を持つ既製の Pico 用エミュレータはないので、映像出力部とダンプ処理は自作になる。（確認済）
4. カセットの容量は PRG+CHR 合計で 256 KB 以下が 86.2%、512 KB 以下が 99.1% で、ダンプ時間は 256 KB で約 2.0 秒、512 KB で約 3.9 秒と見積もられる。（容量は確認済、時間は未確認の計算値）
5. 実チップモードは最小 38 本の端子が要り Pico 2 1 枚（26 本）では足りないので、Pico 2 を 2 枚に分けるか RP2350B（48 本）を基板に直接載せる必要がある。（未確認：机上の割り当て）
6. マイコンは何枚使ってもよいという現行要求に合わせ、Pico 2 を 3 枚（映像の Pico A、バスと入力の Pico B、カセットと管理の Pico C）に分ける構成が推奨され、費用はピンソケット込みで ¥3,720 である。（推論）
7. RP2350 の GPIO を 5V 信号に直結してよいのは IOVDD（3.3V）が入っている間だけで、電源が入っていない間は 3.63V までしか許されないため、5V 側の電源投入を遅らせるか 5V 側の出力を Hi-Z に保つ回路が要る。（条件は確認済、対策は推論）
8. 3.3V 出力で 5V 給電の 74HC を駆動するのはデータシートの規格外で、マイコンから 5V ロジックへ渡す箇所は 74HCT 系にするか 74HC を 3.3V 給電にする必要がある。（確認済）
9. Pico 2 の USB 端子は Micro-B で、USB の信号は 40 本の端子列に出ておらず裏面のテストパッド TP2（USB DM）・TP3（USB DP）にしかないので、USB Type-C から更新するには、ケーブル中継、裏面パッドへの配線、チップ直載せのどれかを選ぶ必要がある。（確認済）
10. USB の書き込み機能は書き換えできない ROM にあり、A/B 区画と TBYB で更新の失敗から戻れるが、複数枚のマイコンを 1 つの Type-C 端子からまとめて更新する方法には一次資料がない。（ROM と A/B 区画は確認済、一括更新は推論）

電源が入っていないときの扱いと対策の候補（いずれも推論）。

- **危険な時間帯（推論）**: JAMMA の +5V が先に立ち上がり、Pico の 3.3V が立つまでの数 ms（未計測）に、5V 側の静的な High（外付けプルアップ、NMOS 出力の High）が FT ピンに 3.63V を超えて掛かる。電源断のときは、Pico の昇降圧 SMPS が VSYS 1.8V まで動くので 3.3V が 5V 系より長く残り、比較的安全である（推論）。
- **対策の候補（推論）**:
  - (a) 5V 側のドライバ（74HC/74HCT）の /OE を、Pico の 3V3 が確立するまで Hi-Z に保つ。
  - (b) FT ピンに直列抵抗（1〜10 kΩ、推奨 1 kΩ）を入れて故障電流を制限する。ただし 3.63V を超えた時点で "very little current" の保証外であることは変わらない。
  - (c) 5V→3.3V 方向には、3.3V 給電の 74LVC 系（5V 耐性入力）を挟む。
  - (d) Pico の 3V3 を検出して P-MOS（SI2301 / AO3401A、JLCPCB Basic）で CPU/PPU/カセットの 5V を後から入れる（ゲートは 2N7002、Basic）。
  - (e) FT ピンにつながる線のプルアップは 5V ではなく 3.3V へつなぐ（/IRQ など RP2350 が見る線）。
  - 部品が最も少ないのは (a)+(b)（推論）。実チップモードで CPU/PPU も含めて守るなら (d)+(b)+(e)（推論）。

## 5. ユーザーに決めてもらうこと、次に確かめること

### 5.1 ユーザーに決めてもらうこと

1. **「Basic 部品のみ」の例外を認めるか。** Type-C 端子と 3.3V→5V の境界部品は、JLCPCB では Extended になる。推奨の既定値: この 2 か所だけ例外（Extended か秋月の手はんだ）を認める。
2. **Type-C 端子への引き出し方。** 推奨の既定値: 第 1 版はケーブル中継（Pico 2 を差し替えられる）、量産版はチップ直載せ。
3. **両方式の持ち方の言い換え。** 「マイコンを挿すか CPU/PPU を挿すか」ではなく「マイコンは常に挿し、CPU/PPU は挿しても挿さなくてもよい」としてよいか。推奨の既定値: そうする。モード選択の DIP スイッチはなくす。
4. **セーブ RAM の扱い。** タイマー方式で動かす市販ソフトのうち 881 本中 217 本がバッテリーバックアップを使う。推奨の既定値: シートに既定値の記載はない（業務用ではセーブの保持は必須ではないと考えられる、という見方のみ）。毎回消すかフラッシュに保存するかを決めてもらう。
5. **データベースにないカセットの扱い。** 推奨の既定値: 起動しない。
6. **GPL-3.0 のエミュレータを使うことによるファームウェアのソース公開。** pico-infonesPlus を改造して載せると、配布するファームウェアのソースを GPL-3.0 で公開する義務が生じる（法的な確認は別の分野）。

### 5.2 次に確かめること（順番どおり）

1. ダンプ方式の成立: Pico 2 と 74HC595/165 のチェーン、ファミコン 60 ピンコネクタの小基板で、MMC1・MMC3・NROM・UNROM・CNROM の実カセットのダンプ結果がデータベースと一致するか、256 KB で数秒以内かを測る。
2. エミュレータの 150 MHz 動作: 150 MHz と 252 MHz でフレーム処理時間とテスト ROM の結果を測り、150 MHz で 60 fps を維持できるかを見る。
3. 15 kHz・240p・CSync（水平・垂直同期を 1 本にまとめた信号）の出力: JAMMA モニタで同期し正しい色が出るか、映像レベル（開放 3.0V・2 kΩ 負荷）を測る。
4. 電源シーケンス: Pico 2 の 3V3 確立前に FT ピンへ 3.63V を超える電圧が掛からないかをオシロスコープで測る。
5. 3.3V 駆動で NMOS の CPU/PPU が動くか: RP2350 から 21.5 MHz（30 Ω 直列）を出し、0〜50 °C で数時間誤動作しないかを見る。不合格なら 74HCT245 か LVC4245A に切り替える。
6. 実チップモードの自動検出: /RST 解除後に ALE や /CS が動くかで、CPU/PPU の有無を毎回正しく判定できるか。
7. 複数枚の一括更新: Pico 2 ×2〜3 をリンク線（と SWD）でつなぎ、管理用の 1 枚に UF2 を書くだけで全枚が更新され、途中の電源断から自動復旧するか。
8. ステッピング（製造版 A2/A3/A4）の確認: 購入品の刻印と `rp2350_chip_version()` を記録する。設計は不具合 E9（入力を有効にした GPIO から電流が漏れる）のある A2 でも動くよう、入力は外付けプルアップ、プルダウンは 8.2 kΩ 以下にしておく。

資料で確かめること: JLCPCB / LCSC での RP2350B / RP2354B と PSRAM の分類・在庫、USB ハブ IC の部品、Pico 2 の USB テストパッドの座標と寸法、ファームウェアから BOOTSEL に入る ROM 関数の名前、NES 2.0 データベース（nes20db）のライセンス。
