# ファミコン本体ハードウェア（RP2A03・RP2C02・周辺回路・カセット端子・コントローラ） - 要約

確度の印: 確認済＝独立した2つ以上の出典、またはネットリスト（どの部品のどのピンがどこにつながるかの一覧）・データシート・実測で確認。単一出典＝出典が1つだけ。未確認＝出典が食い違う、または資料がない。推論＝出典のある事実からの判断。データの日付は 2026-11-10。

## 1. この分野の結論

1. 移植するチップは RP2A03（CPU と音源）と RP2C02（画像処理 LSI、以下 PPU）の2個だけで、どちらも DIP-40 である。全40ピン、60ピンカセット端子、15ピン拡張端子、74139・74373・74368 の配線は、4種類の独立したネットリストと NESdev の逐語図で全ピンが一致した。（確認済）
2. 市販ソフトを動かすタイマー方式では、上下・左右の同時押しを決して合成しない。Battletoads は縦トンネル面で上+下を押すと続行できなくなり、ほかにも Mega Man、Super Mario Bros. 2、Teenage Mutant Ninja Turtles などで不具合が出る。同時押しをコイン・スタートに使う特殊形式は新規開発ソフト専用にする。（確認済。設計判断は推論）
3. $4016 は D0〜D2 だけを、$4017 は D0〜D4 だけを駆動し、残りのビットはオープンバス（どの回路も駆動しないため直前のバスの値が読める状態）のまま残す必要がある。Paperboy など Mindscape 製の6本は、読み値が正確に $41 であることに依存する。（確認済。依存ソフトの一覧は単一出典）
4. タイマー方式では II コン（2P 側パッド）の SELECT・START ビットを 0 に固定し、2P スタートは I コンの SELECT として出す。初代ファミコンの II コンにはこの2ボタンがなく、2P が START を押すと Tetris 2 + Bombliss がソフトロックする。（ボタンがないことは確認済、Tetris 2 の件は単一出典）
5. クロックは 21.47727 MHz の CMOS 発振器1個から CPU pin 29 と PPU pin 18 へ、各 22〜33 Ω の直列抵抗を通して直結で与えられる。量産品 TinyNES が 3.3V の MEMS 発振器とクロックバッファで同じことをしており、任天堂自身の GPM-02 基板も 10 nF の結合だけで動いている。（直結が可能なことは確認済、構成は推論）
6. PPU /RST（pin 22）は +5V に固定し（ファミコン方式）、CPU /RST は PPU より 12 ms 以上（推奨 20〜50 ms）遅らせて解除する。NES 方式（CPU と同時リセット）では Magic John と The Lord of King が起動しない。（非互換ソフトは単一出典、遅延時間は 11.4 ms 以上の実測からの推論）
7. カセットスロット直近の CPU D0〜D7 に 33〜100 Ω の直列抵抗を入れ、CPU データバスにはプルアップを付けない。RP2C02G-0 はデータ線の反射やプルアップで OAM（スプライト属性メモリ）が壊れ、100 Ω の直列抵抗で解消したと報告されている。（直列抵抗は確認済、プルアップ禁止は単一出典）
8. 2K×8 SRAM は 62256（32K×8）の上位アドレス A11〜A14 を GND に固定して代用でき、WRAM /CS の遅延回路と PPU /CS の 330 pF / 30 pF は省略できる。任天堂の GPM-02 と TinyNES がそうしている。（省略可は確認済、62256 代用は量産実績のある単一出典）
9. 純正どおりの 74HC368 は JLCPCB で Extended・在庫 0、秋月でも在庫 0 で、事実上調達できない。JLCPCB の Basic にあるインバータは 74HC14 だけで、74HC373（C5636）と 74HC139（C512773）も Extended である。（分類は確認済）
10. CPU・PPU の出力は VOH の保証が 2.4V しかないので、74HCT・74AHCT・74LS・74ALS の5V ロジックか、3.3V 電源の 74LVC で受ける。3.3V から 2A03 の入力（CLK、/RST など）を駆動するのは直結でよいが、カセットのマッパー（5V CMOS 入力）へは 74HCT245 などを挟む。（3.3V 直結可は確認済、他は推論）

PPU /RST（pin 22）の働き:

- チップの一部を電源投入時の状態に戻す。対象は、クロック分周器、映像位相の生成回路、走査線・画素カウンタ、偶数/奇数フレームの切り替えフラグである。
- さらに次のレジスタを 1 フレームの間ゼロに保つ。PPUCTRL、PPUMASK（$2001）、PPUSCROLL（$2005。VRAM アドレスラッチ「T」、細かい X スクロール、H/V トグル）、VRAM 読み出しバッファ。
- ファミコンはこのピンを +5V に直結している。そのためリセットボタンを押している間も画面が消えない。NES の前面ロード機はリセットボタンで CPU と PPU の両方をリセットし、ファミコンと NES-101 は CPU だけをリセットする。
- PPU のクロック分周器がリセットされるので、PPU をリセットすると CPU と PPU のサブサイクルの位相関係が変わる。PPU リセット後の最初の描画フレームでは OAM（スプライト属性メモリ）が壊れやすい。（単一出典: NESdev ユーザーページ Fiskbit）
- リセット後およそ 29658 CPU クロックより前に PPUCTRL、PPUMASK、PPUSCROLL、PPUADDR へ書いても無視される。PPUSTATUS、OAMADDR、OAMDATA（$2004）、PPUDATA、OAMDMA（$4014）はすぐ使える。VBL フラグ（PPUSTATUS bit7）は電源投入時に不定で、リセットでは変わらず、次は約 27384、その次は約 57165 CPU クロックで立つ。（単一出典: NESdev PPU power up state）

- **pin 44**: 74139 pin 9（2Y3）の出力。M2 と A15 の NAND で、$8000〜$FFFF の M2 High 期間に Low になる。（確認済）
- **pin 45・46**: pin 45 は本体→カセットで、2A03 の音声を増幅したもの（368 の音声アンプ出力）。pin 46 はカセット→本体で、本体の音声出力（RF モジュレータ）へ行く。カセット内で 45 と 46 がつながっていないと音が出ない。拡張音源を持つカセットは、ここで自分の音を混ぜて返す。（確認済）
- **pin 49**: PPU PA13 を 368 の空きゲートで反転したもの。（確認済）
- **pin 17**: 05/07 では PPU /RD 線に 68 pF（C18）が GND へ付いている。（単一出典: HVC-CPU-05 回路図と OpenFC の U4.20 ネットの記述）

機構寸法の要点: ピッチ 2.54 mm、2列×30、カセット基板の厚さ 1.2 mm、基板幅 90 mm、高さ 46.1 mm、カードエッジ部の深さ 10.7 mm、信号パッドの高さ 5.7 mm・幅 1.6 mm、電源パッドの高さ 6.7 mm・幅 2.6 mm（HVC-TGROM-01 実測、確認済）。パッドの位置を測る起点「card edge base」の意味は原ページに定義がなく未確認である。

| 経路 | ルール | 信頼度 |
|---|---|---|

電源の予算（推論）:

- +5V 系の予算は、CPU・PPU・RAM・ロジック・カセットで 0.5 A、余裕を含めて 1 A 以上とし、そこにマイコンと映像変換回路を足す。（推論。根拠は 1.10.4 の 0.35〜0.5 A の実測）
- 基板上の +5V を 4.75〜5.25V に保つ。JAMMA の +5V は配線で電圧が下がるので、基板上で 5.0V 付近になるよう調整する。（推論）
- JAMMA 筐体は安定化 +5V を出すので、7805 は載せない。（推論）
- CPU・PPU に通常ヒートシンクは要らないが、閉じた筐体で連続運転するので PPU 上の通風を確保し、熱で不安定なドナーには後付けできるようにする。（推論）

## 3. 選択肢の比較

以下の評価はすべて推論である。

### 3.1 $4016/$4017 の入力バッファ（純正の 74368 ×2 の置き換え）

| 選択肢 | かかるもの | リスク | 判定 |
|---|---|---|---|
| 案A: 純正どおり 368 ×2 | 回路は実機と同じ | 74HC368 は JLCPCB で Extended・在庫 0、秋月でも在庫 0 で、事実上調達できない | 不採用 |
| 案B: 74HC240 系1個 + 74HC14 + オペアンプ（TinyNES 方式） | 部品の流通は良いが Extended 部品が増える | 量産実績はあるが、Basic 部品だけでは組めない | 候補 |
| 案C: 応答をマイコンと3ステートバッファで作り、368 も 4021 も載せない | 部品点数が最少 | 応答タイミングをファームウェアで保証する必要がある | 候補 |
| シートの推奨 | /PA13 は 74HC14 の1ゲート、$4016/$4017 の応答は3ステートバッファ1個（D0〜D4 だけ駆動、D5〜D7 は駆動しない）とマイコン、音声増幅はオペアンプ | 3ステートバッファ・レベル変換・カセットスロット・DIP-40 ソケットは Extended か秋月の手はんだになる | 推奨 |

### 3.2 パッド入力の注入方法

| 選択肢 | かかるもの | リスク | 判定 |
|---|---|---|---|
| 案A: 実物の 4021（または 74HC165 系）をパッドごとに置き、並列入力をマイコンが作る | 部品が2〜3個増える。74HC165 はロードの極性が 4021 と逆なので反転が要る | タイミングは実機と同じで、DPCM グリッチ時の余分なクロックにも自然に追従する | 推奨 |
| 案B: マイコン（PIO）が OUT0・/OE・M2 を見てシフトレジスタを模擬する | 部品は最少 | 1 CPU サイクル（558.73 ns）以内の応答と、余分なクロックへの正確な追従が必要 | 次点 |

どちらの案でも、出力は3ステートで D0（と必要な D1〜D4）だけを駆動し、D5〜D7 は決して駆動しない。

### 3.3 タイマー方式の時間切れの扱い

| 選択肢 | かかるもの | リスク | 判定 |
|---|---|---|---|
| 案A: 入力を全部 0 にするだけ | 最も単純 | 次の客が前の客の場面から始める | 単独では不十分 |
| 案B: CPU だけをリセットする（PPU はリセットしない） | ファミコンのリセットボタンと同じ挙動で互換性が最も高い | 画面に直前の内容が残る | 候補 |
| 案C: CPU と PPU の両方をリセットして保持し、待機画面を出す | 画面を完全に作り直せる | 解除時に PPU を先に、CPU を 12 ms 以上遅らせないと Magic John などが起動しない。PPU リセット後の最初のフレームで OAM が壊れうる | 候補 |
| シートの推奨 | 猶予中は入力を 0 にし、猶予後に案C で保持し、再開時は PPU→CPU の順に遅延を付けて解除する | 要求ファイルの前提（時間切れでリセットしない）と異なるので、ユーザーの確認が要る | ユーザー判断 |

CPU のクロックを止める一時停止は、2A03 に共通に使える停止ピンがなく（RDY は E 版だけ）、クロックの完全停止の安全性も未確認なので採らない。

### 3.4 ゲームから基板の方式を切り替える手段

| 選択肢 | かかるもの | リスク | 判定 |
|---|---|---|---|
| 案A: $4016 書き込みの OUT1・OUT2 に決まった手順のビット列（合言葉）を出す | 追加の配線なし | 市販ソフトが偶然同じ列を出すと誤動作するので、数十ビット程度の長い固定列にする必要がある | 推奨 |
| 案B: 新規開発カセットに専用レジスタ（$4020〜$7FFF の未デコード領域）を置き、基板が監視する | 基板がカセットのバスを監視する回路が要る | 確実 | 次点 |

基板からゲームへの返信は通常方式のときだけ $4017 D3/D4 に出し、タイマー方式では D1〜D4 をすべて 0 にする。返信は合言葉を受けた後に限るとさらに安全である。

### 3.5 実チップとエミュレーションのどちらを挿したかの設定

| 選択肢 | かかるもの | リスク | 判定 |
|---|---|---|---|
| 案A: DIP スイッチ1極またははんだジャンパ | 確実で安い | 設定ミスの余地がある | 強制設定用に残す |
| 案B: マイコンが自動判別する（例: ソケット上の CPU の M2 が動いているかを見る） | 判別回路とファームウェアが要る | 設定ミスがなくなる | 主にする |

両方のモードで、使わない側の出力がバスを駆動しないよう、バッファの /OE で切り離す。

### 3.6 クロック・リセット・メモリの与え方

| 項目 | 選択肢 | かかるもの・リスク | 判定 |
|---|---|---|---|
| クロック | 純正の2石ディスクリート発振（水晶 + 2SC2021 ×2 + トリマ） | 部品が多く、トリマ調整が要る | 不採用 |
| クロック | 21.47727 MHz の CMOS 発振器1個 + バッファ + 22〜33 Ω で直結 | TinyNES の量産実績あり。デューティ比 45〜55 % 程度の品を選ぶ | 推奨 |
| クロック | RP2350 の PIO で作る | 整数分周にはシステムクロックをその倍数にする必要があり、ジッタも大きい | 不採用 |
| PPU リセット | ファミコン方式（PPU /RST を +5V 固定） | 互換性が高い | 推奨（既定） |
| PPU リセット | NES 方式（CPU と同時） | Magic John と The Lord of King が起動しない | 不採用。ジャンパかアナログスイッチで切り替えられるようにはしておく |
| メモリ | 2K×8 SRAM（6116 など） | 入手困難との報告がある | 不採用 |
| メモリ | 62256 で上位アドレスを 0 Ω 抵抗かはんだジャンパ経由で GND に落とす | TinyNES の量産実績あり。0 Ω 抵抗8個程度で将来の容量拡張に備えられる | 推奨 |

## 4. ユーザー要求ごとの判断

判定の理由と推奨はすべて推論である。

| 要求 | 判定 | 理由 | 推奨 |
|---|---|---|---|
| JLCPCB の Basic Parts のみで実装、部品の種類と点数を減らす | 条件つきでできる | ファミコン側のロジックは少ないが、74HC139・74HC373・3ステートバッファ・レベル変換は Extended で、74HC368 は調達できない。カセットスロットと DIP-40 丸ピンソケットは手はんだになる | /PA13 は Basic の 74HC14 で作り、368 は使わない。足りない部品は Extended か秋月の手はんだで補い、その在庫を部品系シートで確認する |
| CPU と PPU だけをファミコンから移植する | できる | 移植するのは DIP-40 の2個だけで、周辺のデコーダ・ラッチ・SRAM は新しい部品で作れる | 2.9 の設計ルールどおりにし、CPU D0〜D7 の直列抵抗、PPU /RST 固定と CPU /RST の遅延、EXT0〜3 の 10 kΩ、PPU の 10 µF タンタルを必須にする。ドナーは無印 CPU、無印/A/B/C の PPU を避ける |

| タイマー方式（市販ソフト用）の入力割り当て | できる | 1P スタート→I コンの START、2P スタート→I コンの SELECT、コインはゲームに渡さない、という割り当ては市販ソフトの使い方と合っている | 同時押しは合成しない。II コンの SELECT/START と $4016 D1・$4017 D1〜D4 は 0 に保つ。マイク必須のソフト（少なくとも5本）は現行要求のままでは遊べない |

| 通常方式・デフォルト形式（新規開発ソフト用） | できる | 2P 側に START・SELECT の実ビットを出すのは AV ファミコン・NES と同じ見え方なので問題ない | コイン→SELECT は 2.5〜4 フレーム（40〜70 ms 程度）のパルスに整形し、連続投入は待ち行列にする |
| 通常方式・特殊形式（新規開発ソフト用） | 条件つきでできる | 市販カセットで特殊形式が選ばれていると、スタートの瞬間に左右同時押しが送られ、続行不能になるソフトがある | 特殊形式はタイマー方式と同時に選べないようにし、起動時の既定はタイマー方式にする。スタート中は左右、コインのパルス中は上下が読めないことを新規開発ソフトの作法として明記する |

## 5. ユーザーに決めてもらうこと、次に確かめること

### 5.1 ユーザーに決めてもらうこと

1. タイマー方式で時間切れになったときの扱い。推奨の既定値は「猶予中は入力を 0 にし、その後 CPU と PPU をリセットして保持して待機画面を出し、再開時は PPU→CPU の順に遅延を付けて解除する」である。要求ファイルの現在の前提（リセットしない）と異なる。
2. マイクを使う市販ソフト（たけしの挑戦状など、進行に必須なものが少なくとも5本）のために、マイク入力の割り当て（例: 2P ボタン3 → マイク）を設定項目として用意するか。現行要求ではボタン3・4を使わないので、既定は「割り当てない」である。
3. 特殊形式を有効にする手段を、新規開発ソフトからの合言葉と担当者の明示的な設定に限ってよいか。推奨は「起動時の既定はタイマー方式、特殊形式はタイマー方式と同時に選べない」である。
4. 実チップとエミュレーションのどちらを挿したかの設定手段。推奨は「マイコンの自動判別を主にし、DIP スイッチかはんだジャンパを強制設定用に残す」である。
5. 参考基板の使い方。最も近い OpenFC は CERN-OHL-S（派生設計を配布すると設計ソースの公開義務が生じるライセンス）なので、回路を流用するか配線事実だけを参照するかを決める。扱いは法務系シートの範囲である。

### 5.2 次に確かめること（試作基板で、この順に）

1. クロックの直結: 選んだ CMOS 発振器（DC 結合、22〜33 Ω 直列）で E 系と G 系の両方のドナー CPU・PPU が起動し、M2 = CLK/12、デューティ 15/24 になるかをオシロで確認する。
2. リセットの順序: PPU /RST 固定・CPU /RST 遅延（12 ms・20 ms・50 ms）で Magic John または The Lord of King が起動するか。
3. OAM 破損: 2C02G-0 ドナーで CPU D0〜D7 の直列抵抗 33 Ω・100 Ω・0 Ω を比べ、フラッシュカセットでスプライトが化けないか。
4. 3.3V 側との接続: マイコンから /RST、/NMI 監視、OUT0 読み取り、$4016/$4017 応答を行ったときの論理レベルの余裕。
5. 消費電流と、JAMMA 筐体の +5V の基板上の電圧。
6. 熱: 筐体内で長時間運転したときの PPU の温度とスプライトの崩れ。
7. カセットスロット: 候補コネクタ（WingTAT S-60M-2.54-5、LCSC の ED60BGFBK・EC60P03BK、ヒロセ CR22A-60D-2.54DS(70)）で 1.2 mm 厚のカセットの保持力と接触、シェルと部品の干渉。
8. ピン番号: フットプリントの pin 1（正面側の列の左端）と pin 31（その真後ろ）を市販カセットの導通で確認する。
9. 音声: pin 45→46 のループで拡張音源カセット（N163、VRC6 など）の音量差を測り、トリマの範囲を決める。
10. 映像: コンポジットを使う場合、VOUT 配線と VRAM バスの位置関係で縦縞が出ないか。
11. コントローラ応答: ラッチ、8回読んだ後の 1、DPCM グリッチ時の余分なクロックへの追従を、Paperboy（$41 依存）と DPCM を使うソフトで確認する。
12. ドナーチップの判定: 刻印でリビジョンを記録し、M2 の分周比とデューティ（無印は 17/24、偽物は ÷16）、音だけ鳴るテスト ROM、画面テストと長時間の熱ランで検査する。
