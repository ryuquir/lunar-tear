# 07 rev E ファームウェア（Pico 2 ×2 ＋ XIAO RP2350）

rev E 基板（[06_rev_e_plan.md](06_rev_e_plan.md)）用の 3 本のファーム。3 本ともビルド通過、ホストテスト通過、**実機未検証**。

| マイコン | ビルド | 役割 | サイズ |
|---|---|---|---|
| U1 Pico 2（CPU バス） | `-DFC_BOARD=reve_cpu` | PRG・WRAM・マッパーレジスタの応答、書き込みの取り込み、CHR-RAM 書き込みの再現、起動手順、ROM ライブラリ（USB） | text 113 KB / RAM 462 KB（SRAM 520 KB 中） |
| U2 Pico 2（PPU バス） | `-DFC_BOARD=reve_ppu` | CHR・カセット側ネームテーブルの応答、CIRAM /CE・A10、MMC5 の PPU 側処理 | text 40 KB / RAM 450 KB |
| U3 XIAO RP2350 | `-DFC_BOARD=reve_x` | /IRQ（M2・A12・A13 から正確なタイミングで）、MMC5 の $5204 状態、拡張音源 | text 52 KB |

```sh
mkdir build-reve_cpu && cd build-reve_cpu && cmake -DFC_BOARD=reve_cpu .. && make   # reve_ppu / reve_x も同様
cd test && make                                                                       # ホストテスト（rev E 分は test_reve）
```

3 本とも 240 MHz（コア電圧 1.15 V、フラッシュは 80 MHz に落とす）で動かす。

## 時間に厳しい処理の分担

| 処理 | どこで | 方法 |
|---|---|---|
| CPU 読み出しへの応答 | U1 コア 1 | アドレスが変わるたびに PRG と $4020-$7FFF の値を先に引いておき、/ROMSEL が下がったら PRG、上がっていれば WRAM／レジスタを出す。/WS が下がったら即座に手を離す |
| CPU 書き込みの取り込み | U1 PIO0 | /WS 立ち下がりから 220 ns 後に A0-14・D0-7・/ROMSEL を一度に読む |
| 副作用のある読み出し | U1 コア 1 | M2 が見えないので、「アドレスが 300 ns 以上止まり、その間 /ROMSEL も /WS も下がらなかった」ものを読み出しと確定（`core/reve/rcommit.h`）。$2002/$2007、MMC5 $5204、N163 $4800 |
| CHR・ネームテーブル応答 | U2 コア 1 + PIO0 | 新しい PPU アドレスごとにマッパーの PPU フックを呼び、値を PIO に渡す。PIO は /RD が Low の間だけ PD0-7 を駆動（PPU は /RD High の間に同じ線でアドレスを出すため） |
| CIRAM /CE と A10 | U2 PIO1 | A10-A13 の 16 通りに対応するジャンプ表（命令メモリ 0-15）を回し続け、side-set で 2 本を同時に出す。ミラーリングが変わると表を書き換える |
| IRQ | U3 コア 1 + PIO0 | M2 の 1 サイクルごと、PPU の /RD ごとに PIO が FIFO に積み、コア 1 がマッパーの cpu_cycle / ppu_addr を呼ぶ。マッパー状態の変更はすべてコア 1 で順番どおり行う |

## マイコン間リンク（`core/reve/reve_link.h`）

1 本の線を 3 台で共有する半二重。12.5 Mbaud、1 シンボル = スタート＋10 ビット＋ストップ。データ 10 ビット目がフレーム先頭の印で、1 シンボル失っても次のフレームで揃い直す。

| フレーム | シンボル数 | 用途 |
|---|---|---|
| CPU 書き込み | 3 | $4020 以上の全書き込み（MMC5 では $2000/$2001 も） |
| 連続書き込み | 2 | 直前のアドレス + 1（ExRAM の一括書き込みなど） |
| PPU アドレス / データ | 3 / 2 | U1 が再現した $2007 書き込み（CHR-RAM、カセット側ネームテーブル、U2 の CIRAM 写し） |
| 読み出し確定 | 3 | $5204 などの副作用を U2・U3 にも反映 |
| POLL | 2 | U1 が U2/U3 に状態を聞く（MMC5 実行中は 4 µs ごとに U3 へ） |
| LOAD / BULK | 可変 | ゲームの説明（マッパー番号・容量・プロファイル）と CHR 本体 |

送信するのは U1 だけで、U2・U3 は POLL に 1 シンボルで答えるだけなので衝突しない。

## 起動とゲームの切り替え（`core/reve/bootpark.h`）

1. ゲームが動いていない間、U1 は $8000-$FFFF の読み出しすべてに $4C を返す。CPU は電源投入・リセット・ゲーム途中のどれからでも 1 命令以内に「JMP $4C4C」に入る（NMI/IRQ ベクタも $4C4C）。
2. ゲームの準備（PRG を SRAM へ、CHR を U2 へ、マッパー情報を U2・U3 へ）が終わると U1 が合図を出し、次に $4C4C を読んだ CPU には $6C $FC $FF（JMP ($FFFC)）を返す。
3. CPU はゲームのリセットベクタを読んで、電源投入時と同じ状態から始める。順番が崩れた場合はループに戻るだけ。

USB から ROM を書き込むときも、CPU をこの状態で待たせたまま U1 のフラッシュに書き、終わると新しいゲームが自動で始まる。

## ROM の置き場所

- **U1**: 4 MB フラッシュのうち約 3.4 MB が ROM ライブラリ（最大 63 本、PRG と CHR を続けて格納）。PRG はゲーム開始時に SRAM（384 KB）へ写す。入りきらないゲームはフラッシュから直接返し、バンク切り替えのたびに使われるページを SRAM に写していく（`core/reve/romcache.c`）。
- **U2**: CHR はゲーム開始時に U1 からリンクで受け取る（256 KB で約 0.3 秒）。384 KB を超える CHR は U2 自身のフラッシュに書き、同じ CHR なら次回は送り直さない。
- **U3**: ROM は持たない（マッパーのレジスタ状態だけ）。

## MMC5（`core/mappers/m005_mmc5.c`）

rev E に合わせて書き直した。

- **8×16 スプライト**: 2 組の CHR バンクを書き込み時に計算しておき、PPU 側では選ぶだけにした（PPU フックが 1 回の読み出しに間に合う速さ）。8×8 では最後に書いた組を使う（実機どおり。以前は常に A 組だった）。
- **拡張アトリビュート（ExRAM モード 1）**: 全ネームテーブルに適用（以前は ExRAM をネームテーブルにしている場合だけだった）。
- **縦分割画面（$5200-$5202）**: 新規実装。分割側のタイル・アトリビュート・CHR（4 KB バンク、独自の縦スクロール）を返す。
- 分割画面と拡張アトリビュートでは、属性バイトを CIRAM でなくカセットが返す必要があるので、U2 は CIRAM を止めて CPU の $2007 書き込みから作った CIRAM の写しで全ネームテーブルに答える（`nt_full`）。
- **スキャンライン IRQ**: U3 は A13 と /RD しか見えないので、「ネームテーブル領域の読み出しが 3 回続いた」ところを行の始まりとする（各行の末尾 337・339 ドットと次の行の最初の読み出しで、実機が「同じアドレス 3 回」を見るのと同じ時点）。

## ホストテスト（test/test_reve.c、49 項目）

リンクの符号化・復号（1 シンボル欠落からの復帰を含む）、$2006/$2007 の追跡（+1/+32、読み出しでの加算、$2002 でのトグル初期化）、読み出し確定（バス切り替え時の短いグリッチを無視）、起動手順（オペランド読み出し中に合図しても正しく JMP ($FFFC) に入る）、ROM ページキャッシュ（使用中ページは追い出さない）、MMC5（8×16 の組、A13 だけでの IRQ、$5204 の確認、分割画面）。既存の項目もすべて通過（2026-11-08 時点: test_core 1319、test_virtual 16、test_reve 52、test_mappers 524）。

## 未検証・残っていること

- **実機での時間**: CPU 読み出しの応答（/ROMSEL から約 300 ns 以内）、書き込みのサンプル位置（220 ns）、PPU 読み出しの応答、CIRAM /CE の遅れは、すべてロジアナで測って `board_reve_*.h` の定数を合わせる必要がある。
- **電源投入直後**: U1 が起動する前に CPU が動き出した場合、$4C のプルだけでは確実に止められない。映らないときは本体のリセットを 1 回押す（U1 が動いていれば必ず起動手順に入る）。
- **リンクの速さ**: 12.5 Mbaud は 1 kΩ 2 本越しの波形を確認してから決める。だめなら `RL_BAUD` を下げる（バンク切り替えの遅れが増える）。
- **マッパー**: 2026-11-08 に残りを移植済み（[03_mapper_coverage.md](03_mapper_coverage.md)、98 種）。2026-11-10 に自作ソフト向けのマッパー 30（UNROM 512）を追加（`core/mappers/m030_unrom512.c`。フラッシュ自己書き込みは RAM 上の PRG を書き換え、`prg_dirty` を立てる。保存の仕組みは未実装）。rev E 側の対応:
  - 読み出しに副作用のあるもの（N163・MMC5・Maxi 15 など）は `peek()` で値を返し、確定後に `read()` を呼ぶ。
  - Maxi 15（234）はレジスタが ROM の**読み出し**で切り替わる。U1 は /ROMSEL が下がった読み出しを確定扱いにして処理するが、反映は数 µs 遅れる。
  - $4020-$5FFF に RAM や読み返しレジスタを持つ基板（TXC 36、Action 52、603-5052、SHERO、FK23C、Study Box）は U1 の `low_window()` に登録してある。新しい基板を足すときはここも追加する。
  - MMC1 の「連続する 2 回の書き込みの 2 回目は無視」は、U1 では M2 が見えないので、書き込み間隔（1 サイクル ≒ 559 ns、次は 1118 ns）で判定する。
  - CPU の $2007 書き込みは常に U2 へ送る（CHR-RAM・カセット側ネームテーブル・CIRAM の写し）。
