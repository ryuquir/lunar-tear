# ファミコン JAMMA 基板　回路設計（rev 0.2）

日本のファミリーコンピュータ（HVC-001）の CPU（RP2A03）と PPU（RP2C02）を載せ替えて、JAMMA 筐体で動かす基板の設計データです。
調査結果は `reports/ファミコン JAMMA 基板 仕様調査.md`、ユーザー要求は `research_notes/ファミコン JAMMA 基板 仕様調査/user_requirements.md` にあります。

rev 0.2 は「部品の実装をすべて JLCPCB に任せる」版です。自分ではんだ付けする部品はありません。
基板が届いたあとの作業は、ドナー機から外した CPU と PPU をソケットに挿すことと、USB でファームウェアを書くことだけです。

| 版 | 実装の分担 | 場所 |
|---|---|---|
| rev 0.1 | JLCPCB は Basic 部品だけを実装。残りは秋月電子の部品を手はんだ（はんだ付け 約 650 か所） | コミット `35126bd` |
| **rev 0.2** | **JLCPCB がすべて実装（Extended 部品も使う）。手はんだ 0 か所** | この版 |

python3 tools/jlc_parts.py                   # 発注の直前に。在庫と価格を取り直す

`build.py` は次を検査し、1 つでも外れると失敗します。

- 実装する部品がすべて JLCPCB の部品ライブラリにあること。Basic 部品は Basic の一覧、Extended 部品は `data/jlcpcb_extended_parts.csv` と照合します。
- 部品番号が回路の意図した品名・パッケージと一致すること。
- Extended 部品が Standard PCBA で実装でき、5 枚分以上の在庫があること（20 枚分を切ると警告）。
- 手はんだが必要な部品が 1 つもないこと。
- 標準フットプリントが KiCad のライブラリにあること。
- KiCad の電気的規則チェック（ERC）でエラーがないこと。
- KiCad が書き出したネットリストが、回路の記述と 1 ピンずつ一致すること。
- この基板固有の規則 3 つ（3.3V 系の外にある部品は抵抗を通してしか Pico の GPIO につながない／IC ごとに 100 nF／データバスの各ビットの接続が揃っている）。

回路図は「部品とネット名のラベル」だけで描いています（配線は引いていません）。同じ名前のラベルがつながっています。

## 3. 回路の概要

### 3.1 2 つの動作モード

| モード | CPU・PPU のソケット | しくみ |
|---|---|---|
| 実チップ | ドナー機の RP2A03 と RP2C02 を挿す | カセットを実機と同じ回路で動かす。映像は PPU の EXT 端子から色番号を取り出して RGB にする |
| エミュレーション | 空にする | Pico C がカセットの中身を読み出し、Pico A がエミュレータを動かす |

どちらを選んだかは DIP スイッチの 1 番で設定します（OFF = 実チップ、ON = エミュレーション）。
Pico 2 は 3 枚とも基板にはんだ付けされていて、どちらのモードでも使います。CPU・PPU と Pico を同じソケットで差し替える形にはしていません（ピン配置も電圧も合わないため）。

### 3.2 Pico 2 の役割とピン

| 枚 | 役割 |
|---|---|
| A（映像） | CPU・PPU のクロック（21.5 MHz）とリセット。EXT0〜3 とスプライト判定ビットの取り込み。RGB と同期の出力。重ね表示。エミュレーションモードではエミュレータ本体と音声 |
| B（バス） | CPU が PPU のレジスタに書く値の監視。パレット値などを PPU の手前で差し替え。パッド読み出し（$4016・$4017）への応答 |
| C（入出力・管理） | JAMMA の入力と出力、コインとタイマー、カセットの読み出し、USB Type-C、Famicom 側の電源スイッチ、音声アンプの入り切り、A と B の書き換え |

| GPIO | Pico A | Pico B | Pico C |
|---|---|---|---|
| 0 | EXT0（入力） | CPU 側 D0 | ダンプ SER |
| 1 | EXT1 | CPU 側 D1 | ダンプ 高速シフトクロック |
| 2 | EXT2 | CPU 側 D2 | ダンプ 低速シフトクロック |
| 3 | EXT3 | CPU 側 D3 | ダンプ ラッチ |
| 4 | スプライト判定ビット | CPU 側 D4 | ダンプ アドレス出力許可（Low で出力） |
| 5 | ALE | CPU 側 D5 | ダンプ データ出力許可（Low で出力） |
| 6 | R0 | CPU 側 D6 | M2（ダンプ時は駆動、通常は監視） |
| 7 | R1 | CPU 側 D7 | JAMMA 出力の許可（Low で有効） |
| 8 | R2 | PPU 側 D0（差し替え出力） | 入力チェーンのデータ |
| 9 | G0 | PPU 側 D1 | 入出力チェーンのラッチ |
| 10 | G1 | PPU 側 D2 | 入出力チェーンのクロック |
| 11 | G2 | PPU 側 D3 | 出力チェーンのデータ |
| 12 | G3 | PPU 側 D4 | Pico A の SWCLK |
| 13 | B0 | PPU 側 D5 | Pico A の SWDIO |
| 14 | B1 | PPU 側 D6 | Pico B の SWCLK |
| 15 | B2 | PPU 側 D7 | Pico B の SWDIO |
| 16 | 同期（正論理で出力） | CPU A0 | Pico B への送信（パッドの状態） |
| 17 | クロック出力 | CPU A1 | Pico A のリセット |
| 18 | PPU /RST | CPU A2 | Pico A とのリンク クロック |
| 19 | Pico C への送信 | CPU R/W | Pico A への送信 |
| 20 | Pico C からの受信 | PPU /CS | Pico A からの受信 |
| 21 | Pico B からの受信 | /OE1 | Pico B のリセット |
| 22 | Pico C からのクロック | /OE2 | +5V_SW の投入 |
| 26 | CPU /RST | OUT0（分圧） | +5V の監視（ADC） |
| 27 | 音声 PWM | Pico C からの受信 | CIRAM A10 の監視（分圧） |
| 28 | 比較器のしきい値 PWM | Pico A への送信 | 音声アンプの許可（High で動作） |

GPIO0〜22 は、Pico に電源が入っている間だけ 5V の信号を受けられます。GPIO26〜28 は 3.3V までです。

Pico 2 は端面の 40 か所に加えて、次のパッドも基板にはんだ付けします（Raspberry Pi のデータシートが示す表面実装用の使い方です）。

| パッド | Pico A・B | Pico C |
|---|---|---|
| D1・D3（SWCLK・SWDIO） | Pico C から書き換える線（1 kΩ を通す） | 外付けデバッガ用の未実装ヘッダ J16 |
| TP2・TP3（USB の D−・D+） | 未接続 | 基板の USB Type-C 端子 |
| TP6（BOOTSEL） | 未接続 | 基板の BOOT ボタン（SW5） |
| TP1・D2 | GND | GND |
| TP4・TP5 | 未接続（使ってはいけない端子） | 同左 |

### 3.3 電源

| ネット | 供給元 | 行き先 |
|---|---|---|
| `+5V_IN` | JAMMA の 3・4・C・D | 自己復帰ヒューズ（3A） |
| `+5V` | ヒューズの後 | 音声アンプ、同期出力、`VSYS`、`+5V_SW` のスイッチ |
| `+5V_SW` | AO3401A のスイッチ（Pico C が投入） | CPU、PPU、SRAM、5V ロジック、カセット、比較器、オペアンプ |
| `VSYS` | `+5V` と USB の VBUS のダイオード OR | Pico 2 ×3、3.3V レギュレータ |
| `+3V3` | AMS1117-3.3（`VSYS` から） | 入力用シフトレジスタ、JAMMA 入力のプルアップ、JAMMA 出力のシフトレジスタ |
| `+12V_JAMMA` | JAMMA の 6・F | コインカウンタとロックアウトのコイルを切ったときの電流の戻り先だけ。基板の回路は +12V を使わない |

- JAMMA の −5V（5・E）は使いません。
- `+5V_SW` は、Pico C が起動して投入するまで切れています。Pico に電源が入る前に 5V の信号が Pico の端子へ掛かるのを防ぐためです。
- USB だけをつないだときは Pico 2 と `+3V3` だけが動き、Famicom 側と音声アンプは動きません（ファームウェアの書き換え用）。

### 3.4 5V と 3.3V の境界

| 向き | 方法 |
|---|---|
| 5V の信号 → Pico | GPIO0〜22 に直列抵抗（100 Ω〜1 kΩ）を通して直結。GPIO26〜28 へは 10k・20k で分圧 |
| Pico → CPU・PPU（クロック、リセット、データの差し替え） | 3.3V のまま直結（2A03・2C02 の入力は TTL レベルという前提。7 章） |
| Pico → 5V の 74HCT595（ダンプ回路） | 100 Ω を通して直結。74HCT の入力は 2.0V 以上を High と読むので 3.3V で足りる |
| 5V の信号 → 3.3V の 74HC165 | 10 kΩ の直列抵抗で入力保護ダイオードの電流を抑える |
| CPU・PPU（NMOS）の出力 → 5V のロジック | 受ける側を 74HCT にする（デコーダ、NAND、ラッチ）。74HC は 3.5V 以上が必要で、NMOS の出力では保証されない |

ファームウェアの決まり: `+5V_SW` を切っている間、Pico C は 74HCT595 への 6 本を Low か入力にしておきます（電源のない IC へ High を出さない）。

### 3.5 実チップモード

- **バス**: 配線は純正機と同じです。アドレスデコーダは 74HCT138 と 74HCT00、アドレスラッチは 74HCT573、RAM は IS62C256AL ×2（2KB 分だけ使用）です。
- **データバスの抵抗**: CPU と PPU の間に 470 Ω ×8、CPU とカセットの間に 100 Ω ×8 を入れています。Pico B は PPU 側の端子を直接駆動して、PPU に見える値だけを差し替えます。
- **映像**: Pico B が $2000 の bit6 を 1 に差し替えて EXT0〜3 にパレット番号の下位 4 ビットを出させます。スプライトか背景かは、Pico B が PPU のパレットを「背景は暗い色、スプライトは明るい色」に書き換え、VOUT の明るさを比較器（LMV7219）で判定して得ます。本当の色は Pico B が控えて Pico A に送り、Pico A が RGB にします。
- **音声**: 2A03 の 2 本の音声出力を純正と同じ定数で混ぜ、オペアンプで増幅してカセットの 45 番へ出し、46 番から戻った音を D 級アンプ（PAM8302A）に入れます。
- **パッド**: Pico C が JAMMA の入力を読んで方式・形式に従って変換し、Pico B へ送ります。Pico B は /OE1・/OE2 が Low の間、CPU 側のデータバスに応答を出します。

### 3.6 エミュレーションモード

- 74HCT595 ×6（`+5V_SW` で動作）がカセットへアドレスと制御信号を出します。高速側の 4 個は CPU アドレス 16 本と PPU アドレス 14 本に同じ値を出します。低速側の 2 個は R/W、PPU /RD、PPU /WR、ラッチの切り離し、M2 のプルアップ、カセットへの書き込みデータです。
- カセットのデータ（CPU 側 8 本、PPU 側 8 本）は、入力チェーンの先頭 2 個の 74HC165 で読みます。1 バイトあたり 16 クロックです。
- M2 は Pico C が直接作ります。プルアップは 74HCT595 の出力につないであるので、実チップモードでは切り離されます。

### 3.7 入出力チェーンのビット順

`IO_LATCH` を Low にして戻すと、入力が取り込まれ、同時に出力レジスタが更新されます。その後 `IO_CLK` を 1 回入れるたびに `IN_DATA` に次のビットが出ます。

| 順番 | 部品 | 内容（先に出る順） |
|---|---|---|
| 1〜8 | U17 | カセット PPU データ D7〜D0 |
| 9〜16 | U16 | カセット CPU データ D7〜D0 |
| 17〜24 | U23 | +5V_SW の有無、OUT2、OUT1、DIP4、DIP3、DIP2、DIP1、2P ボタン 5 |
| 25〜32 | U22 | 1P ボタン 5、ティルト、テスト、サービス、コイン 2、コイン 1、2P スタート、1P スタート |
| 33〜40 | U21 | 2P ボタン 4、3、2、1、右、左、下、上 |
| 41〜48 | U20 | 1P ボタン 4、3、2、1、右、左、下、上 |

JAMMA の入力は押すと 0 です。出力レジスタ（U24）は QA〜QD がコインカウンタ 1・2、コインロックアウト 1・2 で、1 で通電します。

### 3.8 ファームウェアの書き込み

1. 基板の USB Type-C 端子をパソコンにつなぐ（筐体の電源は入っていても切れていてもよい）。
2. BOOT ボタン（SW5）を押したまま RESET ボタン（SW4）を押して離す。Pico C が USB ドライブとして見える。
3. ファームウェアのファイルをそのドライブへコピーする。
4. Pico C が再起動し、デバッグ用の線を通して Pico A と Pico B を書き換える。

基板の Type-C 端子と Pico C 自身の Micro-USB 端子は同じ信号線です。同時に 2 本つながないでください。

## 5. 既定として採った設計判断

報告書 5 章の「決めていただくこと」のうち、回路に関わるものは次の既定で進めています。変更の指示があれば回路を直します。

| 事項 | この版の既定 |
|---|---|
| 部品の調達と実装 | すべて JLCPCB（Basic と Extended）。手はんだなし |
| マイコン | Pico 2 を 3 枚、基板に直接はんだ付け |
| カセット端子 | 新品の 60 ピン カードエッジ端子。ドナー機の端子も付けられる穴の配置にできるかは、段階 2 で実物の寸法を見て決める |
| IC ソケット | 丸ピン（C2874018）。同じ穴に板ばね型（C2332、$0.13）も付く |
| クロック | Pico A が 21.5 MHz を出す（公称より 0.1% 高い）。水晶発振回路は載せない。外部クロックはテストパッド `CLK` から入れられる |
| PPU のリセット | Pico A が制御する。はんだジャンパ JP1 をつなぐと純正と同じ +5V 固定になる |
| RGB の階調 | 赤 3 ビット、緑 4 ビット、青 3 ビット |
