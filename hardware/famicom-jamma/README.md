# ファミコン JAMMA 基板　回路設計（rev 0.3）

日本のファミリーコンピュータ（HVC-001）の CPU（RP2A03）と PPU（RP2C02）を載せ替えて、JAMMA 筐体で動かす基板の設計データです。
調査結果は `reports/ファミコン JAMMA 基板 仕様調査.md`、ユーザー要求は `research_notes/ファミコン JAMMA 基板 仕様調査/user_requirements.md` にあります。

部品の実装はすべて JLCPCB に任せます。自分ではんだ付けする部品はありません。
基板が届いたあとの作業は、ドナー機から外した CPU と PPU をソケットに挿すことと、USB でファームウェアを書くことだけです。

| rev 0.2 | JLCPCB がすべて実装（Extended 部品も使う）。手はんだ 0 か所。独立レビューの前の版 | コミット `ae6575b` |

## 2. ファイルと作り方

| 場所 | 内容 |
|---|---|
| `design/circuit.py` | 回路の記述（部品、ネット、定数、設計意図の注記）。**これが正本** |
| `design/symbols.py` | KiCad 標準ライブラリにない部品の記号（ピン番号と名前） |
| `tools/build.py` | 回路の記述から KiCad プロジェクトを作り、検査し、費用を計算する |
| `tools/jlc_parts.py` | Extended 部品の在庫・価格・実装区分・X 線検査の要否を JLCPCB から取り直す |
| `tools/fcgen/` | 生成器（回路モデル、部品ヘルパー、KiCad 出力） |
| `tools/setup_env.sh` | 作業環境の準備（KiCad 10 と Python 環境） |
| `data/jlcpcb_basic_parts_2026-11-10.csv` | JLCPCB の Basic 部品 351 件 |
| `data/jlcpcb_extended_parts.csv` | この基板が使う Extended 部品 18 種の在庫・価格・実装区分（取得日つき） |
| `kicad/` | 生成された KiCad 10 プロジェクト（手で編集しない） |
| `out/` | 回路図 PDF、ネットリスト、部品表、ERC の結果、費用の内訳（`cost_estimate.csv`） |
| `ordering/` | 発注代行（GrokBOT）向けの指示書の原稿と、JLCPCB への質問文 |

```
sudo tools/setup_env.sh                      # 初回のみ
python3 tools/jlc_parts.py                   # 発注の直前に。在庫と価格を取り直す
/opt/fcjamma-venv/bin/python tools/build.py  # kicad/ と out/ を作り直して検査する
```

`build.py` は次を検査し、1 つでも外れると失敗します。

- 実装する部品がすべて JLCPCB の部品ライブラリにあること。Basic 部品は Basic の一覧、Extended 部品は `data/jlcpcb_extended_parts.csv` と照合します。
- 部品番号が回路の意図した品名・パッケージと一致すること。
- Extended 部品が Standard PCBA で実装でき、5 枚分以上の在庫があること（20 枚分を切ると警告）。
- 手はんだが必要な部品が 1 つもないこと。
- 標準フットプリントが KiCad のライブラリにあり、記号のピンすべてにパッドがあり、JLCPCB が供給するパッケージと一致すること。
- KiCad の電気的規則チェック（ERC）でエラーがないこと。
- KiCad が書き出したネットリストが、回路の記述と 1 ピンずつ一致すること。
- この基板固有の規則 6 つ。
  - ピンが 1 本しか無いネットが無い（ネット名の打ち間違いの検出）。
  - 3.3V 系の外にある部品は、抵抗を通してしか Pico の GPIO につながない（出荷時につながっているはんだジャンパは 1 本の線として扱う）。
  - IC ごとに、その IC 専用の 100 nF がある。
  - バスの各ビットの接続が揃っていて、欠けたビットが無い（データバス、ダンプ回路の直列抵抗など 10 系統）。
  - 同じ IC の出力が 2 本、同じネットにつながっていない。
  - 5V を受けられない GPIO26〜28 は、5V になりうる線から抵抗で受けるとき、GND への抵抗も持つ（分圧になっている）。
- 極性やピン番号を誤ると検査をすり抜ける部品（電源スイッチ、TVS、ダイオード、PNP、半固定抵抗、比較器、有極コンデンサ、ダンプ回路の許可線）について、データシートから書き起こした事実が成り立つこと（`design/circuit.py` の `selfcheck`）。

回路図は「部品とネット名のラベル」だけで描いています（配線は引いていません）。同じ名前のラベルがつながっています。

## 3. 回路の概要

### 3.1 2 つの動作モード

| モード | CPU・PPU のソケット | DIP スイッチ 1 番 | しくみ |
|---|---|---|---|
| 実チップ | ドナー機の RP2A03 と RP2C02 を挿す | OFF | カセットを実機と同じ回路で動かす。映像は PPU の EXT 端子から色番号を取り出して RGB にする |
| エミュレーション | 空にする | ON | Pico C がカセットの中身を読み出し、Pico A がエミュレータを動かす |

Pico 2 は 3 枚とも基板にはんだ付けされていて、どちらのモードでも使います。CPU・PPU と Pico を同じソケットで差し替える形にはしていません（ピン配置も電圧も合わないため）。

チップを挿したまま DIP スイッチを ON にしてしまっても壊れないように、三重に守っています（3.6 節）。

### 3.2 Pico 2 の役割とピン

| 枚 | 役割 |
|---|---|
| A（映像） | CPU・PPU のクロック（21.5 MHz）とリセット。EXT0〜3 とスプライト判定ビットの取り込み。RGB と同期の出力。重ね表示。エミュレーションモードではエミュレータ本体と音声 |
| B（バス） | CPU が PPU のレジスタに書く値の監視。パレット値などを PPU の手前で差し替え。パッド読み出し（$4016・$4017）への応答 |
| C（入出力・管理） | JAMMA の入力と出力、コインとタイマー、カセットの読み出し、USB Type-C、Famicom 側の電源スイッチ、音声アンプの入り切り、A と B のリセットと書き換え |

| GPIO | Pico A | Pico B | Pico C |
|---|---|---|---|
| 0 | EXT0（入力） | CPU 側 D0 | ダンプ SER |
| 1 | EXT1 | CPU 側 D1 | ダンプ 高速シフトクロック |
| 2 | EXT2 | CPU 側 D2 | ダンプ 低速シフトクロック |
| 3 | EXT3 | CPU 側 D3 | ダンプ ラッチ |
| 4 | スプライト判定ビット | CPU 側 D4 | ダンプ回路の許可（High で許可。DIP 1 番が ON のときだけ効く） |
| 5 | ALE | CPU 側 D5 | 予備（テストパッド `C_SPARE`） |
| 6 | R0 | CPU 側 D6 | M2 の監視（入力のみ） |
| 7 | R1 | CPU 側 D7 | JAMMA 出力の許可（Low で有効） |
| 8 | R2 | PPU 側 D0（差し替え出力） | 入力チェーンのデータ |
| 9 | G0 | PPU 側 D1 | 入出力チェーンのラッチ |
| 10 | G1 | PPU 側 D2 | 入出力チェーンのクロック |
| 11 | G2 | PPU 側 D3 | 出力チェーンのデータ |
| 12 | G3 | PPU 側 D4 | Pico A の SWCLK |
| 13 | B0 | PPU 側 D5 | Pico A の SWDIO |
| 14 | B1 | PPU 側 D6 | Pico B の SWCLK |
| 15 | B2 | PPU 側 D7 | Pico B の SWDIO |
| 16 | 同期（正論理で出力） | CPU A0 | Pico B への送信（パッドの状態） |
| 17 | クロック出力 | CPU A1 | Pico A の RUN（High で動作） |
| 18 | PPU /RST | CPU A2 | Pico A とのリンク クロック |
| 19 | Pico C への送信 | CPU R/W | Pico A への送信 |
| 20 | Pico C からの受信 | PPU /CS | Pico A からの受信 |
| 21 | Pico B からの受信 | /OE1 | Pico B の RUN（High で動作） |
| 22 | Pico C からのクロック | /OE2 | +5V_SW の投入 |
| 26 | CPU /RST | OUT0（ゲートで反転して分圧） | +5V の監視（ADC） |
| 27 | 音声 PWM | Pico C からの受信 | CIRAM A10 の監視（分圧。ADC で読む） |
| 28 | 比較器のしきい値 PWM | Pico A への送信 | 音声アンプの許可（High で動作） |

GPIO0〜22 は、Pico に電源が入っている間だけ 5V の信号を受けられます。GPIO26〜28 は 3.3V までです。
3 枚とも GPIO を使い切っています（空きは Pico C の GPIO5 だけ）。あとで信号が足りないと分かった場合は基板の改版になります。

Pico 2 は端面の 40 か所に加えて、次のパッドも基板にはんだ付けします（Raspberry Pi のデータシートが示す表面実装用の使い方です）。

| パッド | Pico A・B | Pico C |
|---|---|---|
| D1・D3（SWCLK・SWDIO） | Pico C から書き換える線（1 kΩ を通す） | 外付けデバッガ用の未実装ヘッダ J16 |
| TP2・TP3（USB の D−・D+） | 未接続 | 基板の USB Type-C 端子 |
| TP6（BOOTSEL） | 未接続 | 基板の BOOT ボタン（SW5） |
| TP1・D2 | GND | GND |
| TP4・TP5 | 未接続（使ってはいけない端子） | 同左 |
| TP7（1.1V。Pico 2 で増えた 7 個目） | パッドを設けない。真下に銅箔を露出させない（8 章） | 同左 |

### 3.3 電源

| ネット | 供給元 | 行き先 |
|---|---|---|
| `+5V_IN` | JAMMA の 3・4・C・D | 自己復帰ヒューズ（3A） |
| `+5V` | ヒューズの後 | 音声アンプ、同期出力、`VSYS`、`+5V_SW` のスイッチ |
| `+5V_SW` | 電流制限つき電源スイッチ TPS2553（Pico C が投入） | CPU、PPU、SRAM、5V ロジック、カセット、オペアンプ、映像バッファ |
| `VSYS` | `+5V` と USB の VBUS のダイオード OR | Pico 2 ×3、3.3V レギュレータ |
| `+3V3` | AMS1117-3.3（`VSYS` から） | 入力用シフトレジスタ、JAMMA 入力のプルアップ、JAMMA 出力のシフトレジスタ、比較器 |

- 電源電圧は JAMMA の端子で **4.75〜5.25V** としてください。5.5V が Pico 2 と音声アンプの上限で、それを超える定常的な過電圧からは守れません（入口の TVS は瞬間的なサージ用です）。
- JAMMA の −5V（5・E）と +12V（6・F）は使いません。
- `+5V_SW` は、Pico C が起動して投入するまで切れています。Pico に電源が入る前に 5V の信号が Pico の端子へ掛かるのを防ぐためです。
- TPS2553 は電流を約 1.3A（1.2〜1.4A）で制限します。カセットの短絡や故障で筐体電源の大電流が流れ続けることはありません。制限が働くと `+5V_SW` の監視ビットが 0 になり、Pico C が分かります。純正機では 3 端子レギュレータ（7805）が電流を制限していました。それに相当する保護です。
- USB だけをつないだときは Pico 2 と `+3V3` だけが動き、Famicom 側と音声アンプは動きません（ファームウェアの書き換え用）。

### 3.4 5V と 3.3V の境界

| 向き | 方法 |
|---|---|
| 5V の信号 → Pico | GPIO0〜22 に直列抵抗（33 Ω〜1 kΩ）を通して直結。GPIO26〜28 へは分圧（10k/12k、20k/12k、47k/47k） |
| Pico → CPU・PPU（クロック、リセット、データの差し替え） | 3.3V のまま直結（2A03・2C02 の入力は TTL レベルという前提。7 章）。クロックだけは、はんだジャンパ JP2 で 5V 振幅に切り替えられる |
| Pico → 5V の 74HCT595（ダンプ回路） | 470 Ω を通して直結。74HCT の入力は 2.0V 以上を High と読むので 3.3V で足りる |
| 5V の信号 → 3.3V の 74HC165 | 10 kΩ の直列抵抗で入力保護ダイオードの電流を抑える |
| CPU・PPU（NMOS）の出力 → 5V のロジック | 受ける側を 74HCT にする（デコーダ、NAND、ラッチ）。74HC は 3.5V 以上が必要で、NMOS の出力では保証されない |
| CPU の OUT0（パッドのストローブ）→ Pico B | 74HCT00 の空きゲートで受けてから分圧する。CPU の High 電圧が低くても確実に読める |

Pico A と Pico B の RUN 端子は 4.7 kΩ で GND に引いてあり、Pico C が High にしている間だけ動きます。Pico C がリセット中・書き換え中・`+5V_SW` を切っている間は、A と B は全端子を開放した状態で止まり、電源の入っていない Famicom 側へ信号を出しません。

### 3.5 実チップモード

- **バス**: 配線は純正機と同じです。アドレスデコーダは 74HCT138 と 74HCT00、アドレスラッチは 74HCT573、RAM は IS62C256AL ×2（2KB 分だけ使用）です。
- **データバスの抵抗**: CPU と PPU の間に 470 Ω ×8、CPU とカセットの間に 100 Ω ×8 を入れています。Pico B は PPU 側の端子を直接駆動して、PPU に見える値を差し替えます。Pico B が Low に引くと CPU 側の線も下がるので、ファームウェアは「先に CPU 側の値を読み、それから駆動する」順で動かします（3.9 節）。
- **映像**: Pico B が $2000 の bit6 を 1 に差し替えて EXT0〜3 にパレット番号の下位 4 ビットを出させます。スプライトか背景かは、Pico B が PPU のパレットを「背景は暗い色、スプライトは明るい色」に書き換え、VOUT の明るさを比較器（LMV7219、`+3V3` で動作）で判定して得ます。本当の色は Pico B が控えて Pico A に送り、Pico A が RGB にします。
- **VOUT のバッファ**: 純正機と同じ形式（PNP のエミッタフォロワ）です。エミッタの抵抗は 157 Ω で、後期の純正基板（HVC-CPU-GPM-02 の 150 Ω）とほぼ同じ負荷です。バッファの出力は、公開されている実測値（NES のエミッタで同期 0.8V、黒 1.3V、白 2.7V）に近いレベルになる見込みです。比較器へは半分に分圧して入れます。同じバッファから、立ち上げ時の確認用にコンポジット映像（J5、未実装のヘッダ位置）も取り出せます。クロックが NTSC の規格値と 0.1% 違うので、テレビでは白黒になる見込みです。
- **クロック**: Pico A が 21.5 MHz を 3.3V 振幅で出します（同じく 3.3V のクロックを 30 Ω 経由で与える再現機 TinyNES と同じ方式）。ドナーのチップが 3.3V 振幅を受け付けない場合に備えて、はんだジャンパ JP2 で 74HCT00 の空きゲートを通った 5V 振幅（反転、約 10 ns 遅れ）に切り替えられます。**切り替えるときは、先に 1-2 の銅箔を切ってから 2-3 をつなぎます。** 切らずにつなぐと、ゲートの出力と Pico A の端子がぶつかります（100 Ω で電流は抑えてあります）。
- **PPU の /CS**: デコーダ出力と PPU の間に 33 Ω の位置を設けています。74HCT138 は純正機の 74LS139 より速いので、不具合が出たらこの抵抗とコンデンサ（未実装の C21）で純正機に近い遅れに調整できます。
- **音声**: 2A03 の 2 本の音声出力を純正と同じ定数で混ぜ、オペアンプで増幅してカセットの 45 番へ出し、46 番から戻った音を D 級アンプ（PAM8302A）に入れます。
- **パッド**: Pico C が JAMMA の入力を読んで方式・形式に従って変換し、Pico B へ送ります。Pico B は /OE1・/OE2 が Low の間、CPU 側のデータバスに応答を出します。

### 3.6 エミュレーションモード

- 74HCT595 ×6（`+5V_SW` で動作）がカセットへアドレスと制御信号を出します。高速側の 4 個は CPU アドレス 16 本と PPU アドレス 14 本に同じ値を出します。低速側の 2 個は R/W、PPU /RD、PPU /WR、ラッチの切り離し、M2、カセットへの書き込みデータとその出力許可です。
- カセットのデータ（CPU 側 8 本、PPU 側 8 本）は、入力チェーンの先頭 2 個の 74HC165 で読みます。1 バイトあたり 16 クロックです。
- M2 は 74HCT595 の出力（5V 振幅）で作ります。Pico C は M2 を読むだけです。

チップを挿したままエミュレーションにしても壊さないための保護:

| 層 | しくみ | 守れる場面 |
|---|---|---|
| 1 | 74HCT595 の出力許可は、DIP 1 番が ON で、かつ Pico C が許可信号を High にしたときだけ有効になる（許可用トランジスタの GND 側を DIP スイッチ経由にしてある） | DIP が OFF（実チップ）のとき、ファームウェアが誤っても出力は出ない |
| 2 | 許可信号が High の間、CPU は回路でリセットに固定される。2A03 はリセット中、バスの端子をすべて開放する | CPU が挿さっていても、CPU 側のバスで衝突しない |
| 3 | PPU はバスから切り離せないので、PPU の出力とぶつかる線（PPU アドレス 14 本、/RD、/WR）には 1 kΩ を直列に入れた。M2、R/W、データ 8 本には 470 Ω | PPU が挿さっていても、ダンプ回路が PPU の端子へ流す電流は 1 ピンあたり 5 mA 以下（470 Ω の線は約 10 mA 以下） |
| 4 | ファームウェアが、許可の前にチップの有無を調べる（3.9 節） | チップが見つかれば読み出しを始めず、異常を表示する |

抵抗では守れないものが 1 つあります。PPU が挿さったまま読み出しが始まり、/RD が Low になると、カセットの ROM と PPU がデータ線（PD0〜7）で直接ぶつかります。これを防ぐのは層 4 だけなので、チップの確認は省略できない手順です。

許可信号を上げ下げしてから出力が切り替わるまで、約 60 µs かかります（スイッチの読み違いと誤動作を防ぐフィルタのため）。

直列抵抗の副作用（ファームウェアで対応します）:

- バス競合のあるカセット（UNROM、CNROM など）のレジスタへは、ROM の中の「書きたい値と同じ値のバイト」の番地に書きます。抵抗があるので ROM の出力に勝てません（実機のゲームも同じ書き方をします）。
- CNROM の一部（1986〜87 年の任天堂製・バンダイ製）にある保護ダイオードも、力ずくでは破れません。ラッチの上位 2 ビットの 4 通りを試し、正しく読める設定を選びます。
- PPU 側の線（1 kΩ）が Low を出せるのは、74LS の入力 1 個分の負荷までです。それを超えるカセットでは読み誤る恐れがあるので、同じ領域を 2 回読んで照合します。実機で該当するカセットが見つかれば、その線の抵抗を 470 Ω に下げます。
- CPU アドレス 16 本は直結です。UNROM のように 1 本のアドレス線に 74LS の入力が何個もつながるカセットがあり、抵抗を入れると Low が出せないためです。

### 3.7 入出力チェーンのビット順

`IO_LATCH` を Low にして戻すと、入力が取り込まれ、同時に出力レジスタが更新されます。その後 `IO_CLK` を 1 回入れるたびに `IN_DATA` に次のビットが出ます。

| 順番 | 部品 | 内容（先に出る順） |
|---|---|---|
| 1〜8 | U17 | カセット PPU データ D7〜D0 |
| 9〜16 | U16 | カセット CPU データ D7〜D0 |
| 17〜24 | U23 | +5V_SW が正常（1）、OUT2、OUT1、DIP4、DIP3、DIP2、DIP1、2P ボタン 5 |
| 25〜32 | U22 | 1P ボタン 5、ティルト、テスト、サービス、コイン 2、コイン 1、2P スタート、1P スタート |
| 33〜40 | U21 | 2P ボタン 4、3、2、1、右、左、下、上 |
| 41〜48 | U20 | 1P ボタン 4、3、2、1、右、左、下、上 |

JAMMA の入力と DIP スイッチは、押す・ON で 0 です。出力レジスタ（U24）は QA〜QD がコインカウンタ 1・2、コインロックアウト 1・2 で、1 で通電します。
「+5V_SW が正常」のビットは、電源スイッチが切れているときと、電流制限・過熱が働いているときに 0 になります。

### 3.8 ファームウェアの書き込み

1. 基板の USB Type-C 端子をパソコンにつなぐ（筐体の電源は入っていても切れていてもよい）。
2. BOOT ボタン（SW5）を押したまま RESET ボタン（SW4）を押して離す。Pico C が USB ドライブとして見える。
3. ファームウェアのファイルをそのドライブへコピーする。
4. Pico C が再起動し、デバッグ用の線を通して Pico A と Pico B を書き換える。

- 基板の Type-C 端子と Pico C 自身の Micro-USB 端子は同じ信号線です。同時に 2 本つながないでください。使わない側にケーブルを挿したままにもしないでください。
- Type-C 端子と BOOT ボタンは、Pico C の裏側のパッド（TP2・TP3・TP6）でつながっています。万一ここのはんだ付けが不良でも、Pico C 自身の Micro-USB 端子と BOOTSEL ボタンで同じ操作ができます（そのため、Pico C の上面をふさがない配置にします）。
- Pico A と Pico B は、Pico C が RUN を High にしない限り動きません。Pico C にファームウェアが入っていない状態では、A と B 自身の USB 端子からは書き込めません。
- USB 端子には静電気保護の部品を載せていません（素の Pico 2 と同じ条件です）。筐体の外に USB 端子を出す場合は、保護つきの中継端子を使ってください。

### 3.9 ファームウェアが守る決まり

回路は次の動作を前提にしています。段階 4 でこのとおりに実装します。

**電源の順序**

1. Pico C は起動後、`+5V` を ADC で測り、4.5〜5.4V のときだけ `EN_5VSW` を上げる。範囲外なら上げずに異常を知らせる。
2. 上げてから 15 ms 待ち、「+5V_SW が正常」のビットが 1 であることを確かめる。そのあと 1 回でも 0 が読めたら（電流制限・過熱・電圧低下）、`EN_5VSW` を下げたままにして異常を知らせる。
3. `EN_5VSW` を下げたあとは、同じビットが 0 になるまで電源が残っているものとして扱う（スイッチに放電の機能は無い）。
4. `+5V_SW` が切れている間、Pico C は 74HCT595 への 4 本を Low にし、Pico A と Pico B の RUN を Low にしておく。音声アンプは `+5V` が正常なときだけ許可する。
5. カセットを抜き差しする前に `+5V_SW` を切る操作を用意する（基板上の LED が消えてから抜き差しする）。

**エミュレーションに入る前のチップ確認**（DIP 1 番が ON のとき、`+5V_SW` を入れるたびに行う）

1. ダンプ回路を許可しないまま始める。
2. PPU: 比較器のしきい値を約 1.8V にする。ソケットが空なら比較器の入力は約 2.3V で、出力は High のまま動かない。PPU が挿さっていれば入力は 1.7V 以下で、出力は Low になる。クロックもリセット解除も要らない。念のため、クロックを出して同期パルスの有無も見る。しきい値は常に 1.9V 以下にしておく（それを超えると比較器の出力が定まらない）。
3. CPU: Pico A がクロックを出し、CPU のリセットを数 ms だけ解除して、Pico C が M2 の変化を見る。変化があれば CPU が挿さっている。
4. どちらかが見つかったら、ダンプ回路を許可せず、異常を知らせる。
5. 見つからなければ、6 個の 74HCT595 すべてに安全な値（ラッチ切り離し、/RD・/WR・R/W は High、M2 は Low、データ出力は禁止）を入れてから許可する。レジスタの中身は電源投入時には不定なので、この順を守る。「+5V_SW が正常」のビットが 0 の間は許可しない。
6. エミュレーションの間、Pico A は CPU のリセットを Low のままにする。

**カセットの読み出し**

- アドレス側と制御側のシフトレジスタは、1 回の更新（RCLK）でどちらか片方だけを変える。M2 は、アドレスや R/W と同時に変えない（/ROMSEL に短いパルスが出て、マッパーのレジスタが誤って動く）。
- カセットへデータを出す 74HCT595（U15）は、書き込みの瞬間だけ出力を有効にする。
- 許可信号を変えたあと 1 ms 待つ。
- CIRAM A10（ミラーリングの判定）は ADC で読む。この端子（Pico C の GPIO27）はデジタル入力を無効にしておく。

**バスまわり（実チップモード）**

- Pico B のパッド応答は、$4016 では D0・D1（と D2 に 0）、$4017 では D0〜D4 だけを駆動する。ほかのビットは入力のままにする（純正機と同じ「開放バス」を保つ）。
- Pico B は CPU データバス側の端子に内蔵プルアップを付けない（PPU の一部の版で不具合が出ることが知られている）。
- PPU への差し替えは、/CS が下がってから 100 ns 以上あとに CPU 側の値を読み、そのあと PPU 側を駆動する。差し替えるのは必要なビットだけ（$2000 は bit6 だけ。$2001 は差し替えない）。$2000 の bit6 だけは /CS が下がったらすぐ駆動する。
- Pico A は EXT の値を次のように読む。透明な画素では背景パレットの 0 番（4・8・12 と出る）なので、下位 2 ビットが 00 なら 0 番の色にする。描画が止まっている間は常に 0。
- エミュレーション時の ROM イメージは Pico A のフラッシュに置く（RAM には入らない）。カセットが変わったときだけ書き換える。

**マイコンの端子**

- RP2350 の初期の版（A2）には、入力にした端子が約 2.2V で止まる不具合（E9）がある。現行の Pico 2 は対策済みの版（A4）に切り替わっているが、JLCPCB の在庫がどちらかは分からない。版によらず動くように、出力専用の端子は入力バッファを切り、読むだけの端子（M2、EXT、ALE）は読む瞬間だけ入力を有効にし、Pico 同士の受信端子は内蔵プルアップを使う。起動時にチップの版を読んで記録する。M2・ALE・EXT のプルダウン（47 kΩ）は、CPU・PPU の出力に負担を掛けない値にしてあり、A2 の漏れ電流には勝てない。この決まりが守られている限り問題にならない。
- RGB の 10 本は駆動能力を 12 mA に設定する。
- JAMMA の入力は、2 回以上続けて同じ値が読めたら確定する。
- 音声の PWM（エミュレーション時）は、アンプ自身の発振（200〜300 kHz）とその 2 倍から離した周波数にする（350 kHz 付近、または 650 kHz 以上）。近いと、うなり音が出る恐れがある。

| Pico 2 のはんだ付けが JLCPCB 側のステンシル設計に依存している | 確認。ただし発注の備考と質問で解決でき、回路の変更は不要 | 質問文と発注時の備考を用意（8 章）。代替の書き込み経路を 3.8 節に記載 |
| 60 ピン端子は 1.57 mm 厚のカード用で、ファミコンのカセットでは接触圧が設計値の 4〜6 割 | 確認。図面と寸法を再計算して同じ結果 | 部品は変えない（JLCPCB に代わりが無い）。サンプルでの確認を段階 2 の前提にした |

軽微な指摘と注記のうち、回路を変えたもの:

| 変更 | 理由 |
|---|---|
| 比較器の電源を `+3V3` に | 5V 側で使うと、電源が 5.5V のとき定格いっぱいだった |
| 映像バッファを NPN から PNP に | NPN では同期信号がつぶれ、確認用のコンポジット出力が使えなかった |
| コイル出力の保護を「+12V へ戻すダイオードと 12V の TVS」から「15V の TVS」に | 12V 線が先に落ちると 5V コイルのカウンタが誤って 1 回動く恐れがあった。12V 線が 13V を超えると TVS に電流が流れ続けた |
| M2 を 74HCT595 から出す | Pico の端子で直接引くと Low の電圧に余裕が無かった |
| Pico A・B の RUN にプルダウン | Pico C のリセット中に A・B が動き続け、電源の無い側へ信号を出す恐れがあった |
| CPU・PPU の出力に付けたプル抵抗を 10 kΩ から 47 kΩ に（M2、ALE、EXT、PPU データバス、/RD、/WR、R/W） | 純正機より重い負荷だった。純正機に無い抵抗は弱くする |
| OUT0 を 74HCT00 の空きゲートで受ける | 分圧だけでは High が保証されなかった。OUT0 が読めないとパッドがすべて効かない |
| クロックの 5V 切り替え（JP2） | 3.3V 振幅で動かない場合の逃げ道 |
| PPU /CS に直列抵抗の位置 | 純正機よりデコーダが速い。調整できるようにした |
| CA13〜15、PA13、/OE1、/OE2 にプルアップ | CPU がリセット中、ロジックの入力が浮いていた |
| 音量の回転方向、PWM フィルタの定数（6 kHz → 12.7 kHz） | 時計回りで小さくなっていた。エミュレーション時の音がこもる |
| 音声アンプ許可・JAMMA 出力許可・ダンプ線のプル抵抗を小さく | マイコンの初期の版の不具合（E9）とリセット時の内蔵プルダウンに対する余裕 |
| USB 端子を KiCad のフットプリントと同じ品番（HRO）に。VBUS に放電抵抗 | 別メーカー品でランド寸法が合っていなかった |
| 費用に X 線検査費などを追加。計算を `build.py` に組み込み | 見落とし |

回路を変えずに、文書（3.9 節、7 章、8 章）へ反映したもの: ファームウェアの決まり、実機で確かめる項目、配置と発注の注意。

### 6.3 rev 0.3 の変更点の再確認（2026-11-11）

1 回目の指摘を反映した変更そのものを、別の読み手 3 人が「誤りを見つける」目的で読みました（電源と保護／アナログとクロック／rev 0.2 との機械的な差分と検査スクリプト）。

| 観点 | 結果 |
|---|---|
| 新しい部品 | 電源スイッチ、TVS、PNP、USB 端子、はんだジャンパとも、記号・フットプリント・メーカーのデータシートの 3 者でピンが一致 |
| rev 0.2 との差分 | 消えたネット 9、増えたネット 38、変わったネット 97。すべて指摘か設計メモで説明がつき、意図しない変更は無かった |
| 保護回路 | 定常状態では、DIP が OFF のときダンプ回路が有効になる組み合わせは無い |

指摘は 28 件（重大 1、軽微 16、注記 11）でした。

| 指摘 | 対応 |
|---|---|
| **重大**: `+5V_SW` が切れている間、DIP 1 番を読み違える。出力許可線のプルアップが電源の無い 74HCT595 の入力へ流れ込み、許可用トランジスタの寄生ダイオードを通して DIP の線が引き下げられる | 許可用トランジスタと 74HCT595 の間に 47 kΩ と 1 nF を追加。DIP の線は電源の状態によらず 3.0V 以上を保つ |
| 許可信号の立ち下がりが容量結合で出力許可線に乗り、DIP が OFF でも約 1 µs だけ出力が有効になりうる | 同じ 47 kΩ と 1 nF がフィルタになる |
| クロックの 5V 切り替えで、1-2 を切らずに 2-3 をつなぐと出力同士がぶつかる。ゲート入力の抵抗でデューティ比が数 % ずれる。クロック線にプル抵抗が無い | ゲート出力に 100 Ω。入力を 1 本にして抵抗を 235 Ω に。クロック線に 4.7 kΩ のプルダウン。注意書きを追加 |
| USB の VBUS の放電抵抗 10 kΩ では、ダイオードの漏れが多い個体で 3V 近くまで浮く | 1 kΩ に変更 |
| 同期出力の NPN は AO3400A で置き換えられる（部品 1 種の節約） | 置き換えた |
| 検査スクリプトが、わざと入れた故障 22 種類のうち 12 種類を見逃し、1 種類で異常終了する | 検査を強化（6.1 節） |
| 直列抵抗の説明が実際より強い（データ線 PD0〜7 は守れない、470 Ω の線は 10 mA）。アンプの出力、PWM 周波数の注記の誤り | 回路の注記と 3.6 節・5 章を訂正 |
| ファームウェアが守るべき順序（レジスタの初期化、M2 の変え方、電源スイッチの扱い）、PPU の有無のより確実な見分け方、初期版マイコンでの注意 | 3.9 節に追加 |
| 1 kΩ では 74LS の入力 1 個分までしか Low を出せない。24V のコイルは非対応。出力は短絡保護なし | 制約として 3.6 節・5 章に明記 |

2 回目の指摘を反映したあとの回路を、さらに別の読み手で確認することはしていません。変更は抵抗・コンデンサの追加と値の変更、トランジスタ 1 個の置き換えで、機械的な検査（6.1 節）は通っています。

## 8. 段階 2・3 と発注で守ること

レビューで出た、配置・製造データ・発注に関する注意です。

**段階 2 を始める前に**

- 60 ピン端子（C5173310）を LCSC で 3 個買い、実物のカセット数本で勘合を確かめる（`ordering/grokbot_instruction_prep.html` の依頼 2）。
- JLCPCB のサポートへ事前質問を送り、回答をもらう（`ordering/jlcpcb_support_question.txt`）。Pico 2 の実装方法とステンシル、挿入部品と金フィンガーの扱い、費用の不明点を聞く。
- Pico 2 の在庫は 55 個（18 枚分）。枚数が決まったら、JLCPCB の事前購入で確保するかを決める。

**フットプリント**

- 自作が要るもの: JAMMA の金フィンガー、60 ピン端子、半固定抵抗（メーカー図面の 3 本足の配置で）。
- 60 ピン端子: 1〜30 番がカセットのラベル側、31〜60 番が裏側、31 番は 1 番の真裏。実寸で印刷してカセットに当てて確かめる。部品の図面にピン番号が無いので、ここを誤るとネットリストの検査では見つからない。
- DIP スイッチの穴は 1.0 mm に広げる（標準フットプリントは 0.8 mm、メーカー推奨は 0.97 mm）。
- Pico 2: TP7（原点から +1.0 mm、−5.0 mm の位置）の真下に直径 2.5 mm の銅箔禁止域。3 枚のモジュールの下のビアはレジストで覆う。

**配置**

- 捨て基板（幅 5 mm）は金フィンガーの辺と直交する 2 辺に付ける。位置合わせマークを 3 か所。
- 挿入部品は金フィンガーから 5 mm 以上、ほかの基板端から 2.5 mm 以上離す。
- 60 ピン端子の横に、カセットを押さえるガイド用の取り付け穴（めっき無し）を 2〜4 個と、カセットの殻の大きさの部品禁止域。寸法は実物のカセットを測って決める。カセットの向き（ラベル側）をシルクで示す。
- IC ソケットの近くに基板の支えを置ける位置（取り付け穴）。チップを挿すとき 10 kg 近い力が掛かる。
- Pico C の上面（Micro-USB 端子と BOOTSEL ボタン）をふさがない。
- 電源スイッチの電流設定抵抗は IC のすぐ横。入口の逆接続保護ダイオード（SS54）と音声アンプの下は銅箔を広く取る。
- ダンプ回路の許可線の 47 kΩ と 1 nF は、許可用トランジスタのすぐ横に置く。
- 5V クロック用ゲートの出力（U5 の 11 番）からジャンパ JP2 までは短くし、隣の OUT0 の入力（10 番）から離す。
- DIP スイッチの「ON」と番号、ソケットの切り欠き、Pico の USB 側をシルクで示す。JP2 の横に「先に 1-2 を切る」、コイン用出力の横に「5V/12V コイル専用」と入れる。

**製造データと発注**

- 発注の備考に書くこと: Pico 2（U25〜U27）はリフローで実装し手はんだにしない。端面の 40 パッドのステンシル開口は 3.8 × 2.2 mm（Raspberry Pi のデータシート 図 6）。デバッグ用の 3 パッドも同じ。裏面のパッド TP1〜TP6 にもはんだを印刷する。金フィンガーは耐熱テープで覆い、はんだやフラックスを付けない。
- 部品の向きを JLCPCB の配置確認画面で見る（有料 $0.45）。特に、極性のある 2 端子の部品（ダイオード SS14・SS54、TVS の SMAJ15A、LED。JLCPCB の部品データは KiCad とピン番号の付け方が逆のものがある。SMAJ15A が逆だとコイン用出力が GND に短絡する）、RAM の 1 番ピン、電解とタンタルの極性、Pico 2 の向き（JLCPCB の部品データは KiCad と 90 度違う）、DIP スイッチの向き。
- 届いたら 1 枚ずつ確かめること: Type-C 端子をつないで USB ドライブが見えるか（TP2・TP3 の確認）。ファームウェアを書いたあと、BOOT を押しながら RESET でもう一度ドライブが見えるか（TP6 の確認）。マイコンの刻印の版（A4 か）。
- チップを挿す前に、足のはんだを取り除いてまっすぐにする。丸ピンのソケットは、はんだの付いた太い足を受け付けない。
